- The user supplied a Token4AI dashboard screenshot and requested a simpler interface grounded in actual API data. - Data audit by gpt-5.6-sol in the isolated read-only `F:/GO/sub2-ui-reference-review` found that `total_*` has inconsistent backend periods: the hourly aggregate path sums retained rows without a 30-day lower bound (`usage_log_repo_dashboard.go`, `fillUserDashboardUsageFromHourlyUsers`), while the raw-log fallback is 720 hours. **This supersedes the earlier assumption that all totals mean exactly 30 days.** Labels now say recent totals. Platform usage keeps its explicit 30-day scope, quota windows retain their own labels, and no synthetic other-platform spend is derived by subtracting mismatched periods. The backend discrepancy is recorded, not changed in this frontend task.
- Charts use the existing authenticated `usage/dashboard/snapshot-v2` contract with trend/models enabled and groups disabled. This replaces two HTTP requests with one; it does not claim fewer backend aggregation queries. Chart mode switching is local, with a total series using the returned `total_tokens`; the existing input/output/cache/rate breakdown remains available. Model percentages use all returned model tokens, not only the three visible legend entries. No invented growth percentages or decorative data were added.
- Platform quotas and recent requests load only after disclosure expansion. The recent query requests five rows instead of fetching 100 and slicing, retains selected dates and explicit descending order, and includes cache read/creation tokens in displayed totals. The backend still executes its normal count query when expanded. Successful results are reused until refresh/date change; errors are distinct from valid empty results and can be retried.

In-flight recent data is invalidated on date changes even when its disclosure has been closed. No backend, database, server configuration, accounting, pricing, order or protocol-conversion code changed.
