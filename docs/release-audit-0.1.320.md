- 新版本先1%，至少观察180秒及12次成功守护检查，并要求每个入口至少50个真实业务完成样本且有成功响应。实际1%观察约7分钟后全量，全量后继续观察超过7分钟。
- 全量时两机319均保留为nginx backup，全部原应用PID保留，不停止应用或截断长连接；只做nginx配置校验及平滑reload。
- 守护仅允许0%到1%、1%到100%的阶段转换；每阶段备份配置，并核对配置指纹，检测外部后续部署时自动解除守护，拒绝用过期模板回滚。
- 两机各自安装systemd timer，检查间隔为上次完成后10秒。公网health/readyz、入口本地readyz、两机319/320直连readyz、原PID与应用状态均须正常。
- 用户在灰度期间明确要求上游502/503不触发回退，两机守护已切换 `platform_health_only`：只有公网/候选健康、候选PID、资源余量异常或候选健康探针错误自动回退。入口业务5xx仅观测，不凭未归因的总错误率回退。
- 候选RSS上限17GiB、整机可用内存底线8GiB。回退前逐次确认至少一个319健康；没有健康319时保留现有路由和守护，不把正常320切到坏备用。原319故障本身不会触发候选回退。
- 回退只恢复本机入口到两机319主服务（保留318备份），不停止任何应用。两机独立检查；nginx已有失败转移同时保留。
- 不把单次旧上游503当成新版本故障。守护与回退输出不包含密钥、正文或用户邮箱。
- 回退事务先持久化前后配置；被中断后识别自身未完成操作并恢复，重新检查319健康，成功reload后重新计时。慢请求按最近完成窗口统计，不漏掉耗时超过180秒的错误。
- 13项临时目录模拟通过，包括健康失败、上游业务错误不误回退、配置校验失败、阶段权重、过期守护拒绝覆盖、回退中断恢复、备用失效、灰度样本不足、恢复后重新计时。所有nginx/systemctl操作均为mock，未在生产故障演练。
