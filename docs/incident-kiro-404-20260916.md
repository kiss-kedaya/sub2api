## 代码修复边界

- 仅识别 HTTP 404 且完整 HTML 文档开头、标准 404 title/h1、nginx 页脚特征。不依赖可缺失的响应头，不把任意 JSON、正文中的 HTML 或资源不存在错误当线路故障。
- 确认路由故障后交给现有 handler 换账号，首个失败响应不提交给下游。
- Anthropic 普通与透传的内部重试遇到该响应立即退出，避免自定义错误码配置导致同线路最多重复五次。
- OpenAI 透传复用同一窄判定；统一 failover 构造器禁止被池模式再次打开同账号重试。
- 保留显式临时不可调度规则，但该路由响应不能被自定义404规则永久标记凭据错误。普通模型不存在/文件不存在/响应不存在仍走原逻辑。
- 不新增平台，不更换模型能力，不改缓存计费、流式输出或首字计时。

## 经验

- 分组名不是平台枚举。先查真实账号和失败请求，不凭名字补适配器。
- 暂停坏线路前后都要检查模型覆盖，避免别名只落在一个供应商上。
- 分类器的布尔字段不一定控制所有调用点；内部重试、池重试、永久处罚要分别核查。
- 版本上线结论有时效。每次接手重读 nginx 路由、守护状态和真实请求。
- 候选端口须查所有 TCP 状态，不能只看 LISTEN。本轮发现8094已被325的Redis出站连接占用，不中断该连接。
