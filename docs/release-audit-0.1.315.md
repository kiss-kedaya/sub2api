## 运维经验

1. 1%灰度的低RSS不能用于预测100%负载，更不能忽略旧请求排空期间的新旧进程内存叠加。
2. 全量前先核对整机可用内存、旧实例RSS及在途请求。候选守护增加8GiB可用内存门槛，低于门槛回退；这只限制发布，不更改生产业务配置。
3. 运行时PID变化后必须重新核实原因。不能沿用旧PID的回退脚本，也不能修改已有事故状态和备份掩盖发生过的回退。
4. 缓存必须同一请求核对上游字段、下游序列化usage和本地账单。缓存未命中0与字段丢失是不同问题；钱包并发变化不能用于单笔归因。
5. nginx按请求完成时间记录，阶段统计需使用完成时间减耗时，排除上阶段长连接尾流。
6. 发布tag必须在完整检查后创建；314旧tag已取消发布，不移动、不复用。
