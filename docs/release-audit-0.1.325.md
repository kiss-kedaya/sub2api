## 证据与边界

- 323 上线后用户再次报告 Grok 首字接近总耗时。约 30 分钟样本中，升级前后均有此现象：29145 升级前 72/2333、后 20/1103；29155 升级前 26/3046、后 13/1613。判定为 first_token_ms >= duration_ms - 50，不等于每条都由同一缺陷造成。
- 普通 Chat 和 Responses 公网实测均正常分段：Chat 首正文 23.388 秒、总 27.404 秒、371 正文片段；Responses 23.483/27.027 秒、332 片段。不能把少数样本解释成全站流式失效。
- 自定义工具真实请求 97444ebe-1157-9bc1-b7c8-d53a0b7e3c2a：推理和正文正常流式，5717 字符 custom 参数在 75.581 秒仅一个 delta 后紧跟 done，总 76.878 秒。代码确认旧 Restorer 吞掉所有 function_call_arguments.delta，直到 done 才还原 custom 输入。
- function 对照请求产生 message 后达到输出上限，未产生工具调用；不能用它们证明上游参数是否分片。确定性服务测试使用分片参数且扣住终态，确认转换层缺陷与修复效果。
- semantic TTFT 还会受到 output_item.added 到达时间影响。不得把此次修复描述为消除了所有首尾相等样本，或通过修改计时口径掩盖上游等待。

## 修复与审查

- 首个根 input 字符串按新到字节增量处理，解码委托 encoding/json。跨片转义、UTF-8、Unicode 代理对不拆坏，不把 JSON 包装发送给客户端。
- 根键不是 input、非规范结构或过长前缀保持完整参数兜底，不误取嵌套 input 或字符串中的同名文本。
- 每个下游事件连续编号、保留 item/call ID；参数 done 仅补尾，不重复内容。省略工具 done 的成功响应快照也补齐生命周期。
- 完成后的参数快照必须完全一致，变更会明确返回协议错误，不能静默下发矛盾参数。失败/取消终态不伪造成功工具结果。
- 计费、缓存、重试预算、数据库和服务器容量配置不变。tool_search 没有自由文本 delta 契约，本轮不强行转换。
- 首版 324 已取消构建，没有发布包、没有部署。324 的完整前缀重扫和根键匹配风险在上线前被发现，325 改成正常路径 O(N) 扫描；不移动旧标签。

## 本地验证

- EverySplit 覆盖每个分割点、转义键、控制字符、孤立及成对 surrogate、嵌套字段。另测逐字节 UTF-8、非法转义、终值变化、重复 done、缺 done 和成功终态快照。
- 同一机器 64KiB/16 字节分片微基准：未上线 324 约 167.5ms、595.9MB 分配；线性实现约 1.16ms、2.45MB。单次微基准不是线上吞吐收益保证。
- 三包 unit 完整测试曾通过 service 210.865 秒、handler 138.992 秒、apicompat 0.781 秒；最后收尾边界变更继续由定向 race 和最终 CI 验证。
- 两名独立代理完成只读审查与独立服务回归。确定性服务测试通过完整 forwardGrokResponses 路径，终态释放前收到参数分片，最终参数无重复、序号连续、usage/cache 保留。
