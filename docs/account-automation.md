# 账号自动化

OAuth 初始模板、真实成功后升并发、组内经营排序及本地随机题质检，均为明确启用的独立功能。新安装不启用任何策略，不包含倍率、模型映射、充值优惠、ModelTrace、受控实验或子代理限制。

OAuth 模板只设置新账号的并发、priority、load factor 和分组。相同平台的分组在保存和使用时都验证，观察者管理员不继承全局模板。现有凭据、价格倍率与模型映射不改。

并发晋升仅统计文本接口的真实成功终态。HTTP 200 加输出片段、`[DONE]`、有实际用量均不足以证明成功；流式需协议终态，取消、EOF、错误帧均不晋升。请求线程只推有界队列，数据库在后台用行锁、设置 revision、开始时间和唯一事件 ID 校验。人工修改并发后重置进度。队列满或写失败立即暂停该实例晋升，管理员重新保存设置才恢复；界面显示此状态。

组内排序不触碰分组遍历、sticky/previous-response 归属、资格筛选、协议优先、利润门和并发获取。排序只在现有相同 priority 与协议层内使用。统计由后台读限定 group/account/model/time 窗口；请求线程只看最长45秒缓存，冷启动或失败保留原序，未知样本不冒充零延迟。质量缺失取中性值。临时失败不修改账号调度开关。

本地题复用参考 fork 的路径计数和加权 XOR 出题/求解器，每轮使用新随机种子，答案由程序计算。仅保存题号、题型、结论和耗时；不保存提示词、参考答案、上游正文、URL或凭据。未启用时不发送请求。每次手动或计划执行会使用真实上游并可能收费；受测请求最多90秒，包含可选判题最多150秒，租约4分钟。响应捕获限1MiB，必须收到显式成功终态，传输失败只记不确定，不能当作质量不通过。

判题方式可选本地确定性比对、独立LLM及Jev原生选择判题。LLM必须指定判题分组和模型，检查模型允许名单、可调度状态和账号并发，并排除受测账号。只比较参考值与候选答案，不把题目发给判题模型重做。Jev复用已启用的TypeSafe审计凭据、代理和轮换算法，但使用独立游标与健康状态，不更改审计池。拒绝格式歧义、重复字段、越界概率和不确定结果；Jev置信与对应概率都至少0.9才接受明确结论。判题请求失败、限流、不确定均不隔离或恢复账号。

暂停归属按计划单独 token 持有。通过后仅解除自身 token，其他本地计划、掺水检测或人工暂停均保留；账号版本变化时不自动恢复。管理员可先预览 fence，再确认恢复/删除。不能恢复时删除会放弃本计划标记但继续保持账号暂停，避免把人工修改覆盖。所有接口硬限制 ID1。

新计划默认仅观察，隔离范围默认仅失败模型；也可明确选择指定组或整账号。模型隔离写入独立运行时标记，其他模型继续服务。指定组范围先隔离该组中的失败模型，只有同组全部启用检测计划都有当前版本的失败归属时才摘除此组，保留其他分组。恢复保留原绑定优先级与创建时间，并校验账号版本和由数据库触发器维护的绑定版本；人工重新绑定后不自动覆盖。调度、旧会话与候选复核使用同一请求组上下文检查标记，不查询数据库热路径。

OAuth/API后备默认关闭。开启后只在同组、同优先级和协议能力层内，使用缓存中的有效质量结论、新鲜额度和当前容量确认OAuth优先；额度、质量或容量不合格时API排在其前。冷缓存沿用原序，并在后台补充证据。它不修改分组遍历、价格倍率、资格、利润门或已有会话绑定。

新OAuth先测后放行默认关闭，配置平台及检测模型后只影响之后新建账号。创建时在同一条账户记录持久化准入标记，数据库触发器记录归属；后台使用有租约的真实随机题检测，仅明确通过且账号版本/标记/租约匹配才解除本次准入暂停。失败、不确定、人工改动不放行；已有质量暂停和到期状态仍独立生效。关闭开关不自动释放已持有的准入暂停。
