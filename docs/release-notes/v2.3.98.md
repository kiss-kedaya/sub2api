# 2.3.98

## 修复

- **OpenAI 分组只有一个可用账号时，上游抖一下不再整组 503 满 45 秒**：同一账号同一模型连续
  出错 3 次会被暂停 45 秒。暂停期间这个分组（或智能路由密钥的全部候选分组）如果没有别的
  可用账号，之前所有请求都直接返回 503「Service temporarily unavailable」，请求根本没有发给
  上游。现在这种情况下请求照常发给上游：上游已经恢复就立刻恢复；上游还没恢复，返回的是
  上游的错误。
  - 分组里还有别的可用账号时行为不变，被暂停的账号照旧让路。
  - 账号被封禁、限流、超并发、模型不支持、本次请求里已经失败过的账号，都不会被放行。
  - `/responses/compact` 请求同样适用。
  - 带 `previous_response_id` 的会话：账号只是被暂停时不再丢掉会话和账号的对应关系，放行后
    继续走原账号，上下文不断。
  - 放行时网关日志里有 `openai_model_transient_fail_open`（每 5 秒最多一条，带这段时间放行的
    次数）。

## 升级注意

- 无数据库迁移，无前端改动。
- 上游真的不可用时，单账号分组的请求会打到上游并返回上游的错误，不再是本地秒回的 503。
