# 2.3.104

## 计费

- **上游明确报错的请求不再扣费（Anthropic 系网关）**。规则：上游自己返回了错误——HTTP 4xx / 5xx 错误响应、流里明确的错误事件、
  HTTP 200 的错误信封——这条请求就不向用户收费，即使上游在报错之前已经报过用量。断流（上游没有明确报错、连接中断或缺结束帧）、
  用户自己断开、网关空闲超时：收费方式不变。
  - **`/v1/messages` 流里「只有 data、没有 event 行」的报错**：以前不被当成报错，要等到流结束才按断流处理，会把上游之前报的用量
    （比如开头的几十万 token 缓存写入）照扣，还会多返回一条 `Upstream request failed`。现在和标准的 `event: error` 一样立即结束、
    不扣费，只返回上游那一条错误。
  - API-key 透传账号：流里明确报错的请求保留用量记录，费用为 0。
  - Chat Completions / Responses 转 Anthropic 的流式和非流式：上游明确报错（含没有 event 行的）不扣费；报错后又正常完成的照常收费。
  - 非流式响应本身是错误信封（`type: error`，或只有 error 对象没有正文）的不扣费。
  - 用户已经断开、随后才读到上游报错的，不再按「用户断开」去收费。
- OpenAI 兼容网关、DeepSeek 联网搜索、Gemini 的同类改动在下一版；Bedrock、Antigravity、WebSocket 和图片接口这次没有改。
  审核 / 风控类拒绝（如 Grok 违规拒绝的固定收费）不在这次范围内，收费方式不变。

## 升级注意

- 无数据库迁移，无前端改动。
- 用量记录里这类请求可能仍有一行（保留了 token 数），金额为 0。
