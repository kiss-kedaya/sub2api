# v2.3.161

本次为「界面」版本：创建密钥第一步没填就不让往下走并标红缺项、「更多设置」展开有动画、全站去掉樱花、圆角统一成连续圆角。**只有前端改动，后端、数据库、扫链代码都没有变化，无数据库迁移。**

## 亮点

- **创建密钥第一步：名称和分组没填就不能进下一步，缺哪项标红哪项**：以前点「下一步」只弹一条吐司，名称为空甚至根本不拦（「下一步」不是提交按钮，浏览器的必填校验不会触发），用户会一路走到身份校验那一步才被服务端拒绝。现在名称（去掉空白后为空）和分组（开了智能路由时看路由列表是否为空）都是必填：缺哪项拦哪项，缺的项一起红边 + 红字，焦点落到第一个未完成项并轻轻抖一下；刚打开的空表单不会一片红，填好后红色实时消失，关闭 / 重新打开不残留。「减少动态效果」下不抖，红字仍在。（#616）
- **「更多设置」展开 / 收起有动画**：以前一帧从 0 跳到整块高度，弹窗随之跳一下；现在高度 + 透明度 220 ms ease-out，可以中途反向（从当前高度接续，不会弹回满高或归零）；「减少动态效果」下直接完成；编辑密钥的弹窗里该区块始终展开，不播动画。（#620）
- **全站去掉樱花**：右侧的水墨樱花树画布和飘落的花瓣都删了（约 1200 行）。粉色主题色保留——那是配色，不是动画。实测它在主线程上只占约 10%，所以首屏变快的幅度有限，主要是去掉了每个页面常驻的一块全屏画布和一层随滚动不断量页面元素位置的脚本。（#617）
- **图表取主题色不再触发 GPU 读回**：仪表盘图表把主题色转成十六进制时，原来每个颜色都画一块 1×1 画布再读回像素，冷加载时合计约 0.4 秒的主线程停顿；现在直接让样式引擎换算，结果与原来逐个相同（亮色 / 暗色各 4 个主题变量核对过）。（#617）
- **连续圆角覆盖到自己写圆角的组件**：全局的连续圆角（squircle）规则以前只命中带 `rounded-*` 类名的元素，侧栏 logo、顶栏余额、指标卡、使用记录表格等在组件自己的样式里写圆角，一直是普通圆弧，和旁边的连续圆角并排时看得出来。逐个页面逐个元素量过（亮 / 暗两套）：改前 8 类共 64 个元素是圆弧，改后为 0。药丸和圆形刻意不动（变成连续圆角会让两端变方）。（#618）

## 变更清单

### 新增

- `utils/collapseMotion.ts`：折叠区高度动画（Web Animations），带中途反向和 `prefers-reduced-motion` 处理（#620）
- `dashboardUi.spec.ts`（此前该文件没有测试）和 `collapseMotion.spec.ts`（#617、#620）

### 优化

- 创建密钥的必填校验与错误展示（#616）
- 仪表盘取色不再 `getImageData`（#617）
- 连续圆角的覆盖范围（#618）

### 移除

- 樱花树画布与飘落花瓣：`InkSakura`、`SakuraPetalField` 及其辅助文件和测试（#617）

### 测试

- 修掉一条会随机失败的测试：「回填被改过的分享码」把分享码末位字符换掉当「损坏」，但无填充 base32 的末位可能带填充位，换掉后解码结果不变，校验和照样通过（旧写法 40 次里约 4 次失败，改后 0 次）。只改测试，没有任何生产代码改动。（#619）

## 升级与兼容说明

- **数据库迁移**：无。后端二进制行为不变，只是前端静态资源随二进制更新。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **主题**：`theme_primary = sakura` 仍然是默认主题色，只是不再有樱花树和花瓣；后台外观设置不受影响。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 暗色登录页的主按钮本来是药丸，但被全局的 `button` 规则命中成了连续圆角（改动前就是这样，本版没有改变）。
- 首屏仍有约 1.5 MB 的第三方库在 `vendor-misc` 里（gzip 约 436 KB），其中一部分只有个别页面用得到；拆分它要改打包配置和若干页面的静态导入，风险比本版大，单独处理。
- 「动画与界面质感」整体打磨只做了量出来确实缺的一项（「更多设置」展开）；其它页面还没有逐个采样。

## 部署

1. 从 Release 下载 `sub2api_2.3.161_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。
