# v2.3.162

本次为「登录体验 + 首屏第三方请求」小版本：登录凭据填错时不再弹出 6 位认证器输入框、每个页面不再向支付厂商发请求、后台模式下绑了 Passkey 的管理员能完成登录。无数据库迁移，扫链代码无改动。

## 亮点

- **登录凭据填错时不再弹出认证器输入框**：开着全站 TOTP 登录验证时，邮箱或密码填错也会拿到一个与「已绑认证器、需要动态码」完全相同的挑战（这是防止登录接口被拿来枚举账号的刻意设计）。以前前端收到挑战就直接弹 6 位码框，没绑认证器的人填错密码会被吓一跳。现在先显示「请核对邮箱和密码。已绑定认证器的用户可以使用动态码继续登录。」和一个「使用认证器验证」按钮，点了才出现 6 位码框（并自动聚焦）；改邮箱或密码会清掉挑战；凭据真的错时 `/auth/login/2fa` 仍统一返回「邮箱或密码不正确，请重试」。**已绑定认证器的用户每次登录多点一下这个按钮。** 后端：全站关闭 TOTP 登录验证时，凭据错误直接返回 `INVALID_CREDENTIALS`，不再下发没有意义的挑战；认证失败审计对所有登录错误都记原因。（#606，外部贡献，感谢 godissogood）
- **每个页面不再向支付厂商发请求**：Airwallex 支付 SDK 只在支付页用，但此前被打进了每个页面必载的公共包，模块一执行就会去 `static.airwallex.com` 和 `checkout.airwallex.com` 拉两份脚本——任何用户打开任何页面都会多一次跨境第三方请求。现在它是独立的懒加载包，只有进入支付页才会取。实测：dashboard / 密钥 / 登录三个页面的 airwallex 请求从 2 个变成 0，传输少约 134 KB，到网络空闲的时间约缩短 30%；首次绘制时间基本不变（这个包本来就不挡首次绘制）。支付页行为不变（新旧发出同样的请求序列）。新增守卫测试防止被改回去。（#623）
- **后台模式下绑了 Passkey 的管理员能完成登录**：账号同时绑了 TOTP 和 Passkey 时，密码登录后的第二因子走 `/auth/login/2fa/passkey/finish`，后台模式的放行表漏了它，这类管理员过完密码和 TOTP 后会在 Passkey 这一步被 403。现在放行；该处理函数自己仍只放行管理员。这是潜在问题（线上没开后台模式），顺手修掉。（#622）

## 变更清单

### 修复

- 登录凭据错误时误弹认证器输入框（#606）
- 后台模式放行表漏掉 `/auth/login/2fa/passkey/finish`（#622）

### 优化

- Airwallex SDK 单列为懒加载 chunk（`vendor-airwallex`），不再进入必载的 `vendor-misc`（#623）

### 测试

- `backend_mode_guard_test.go` 新增 6 个用例（放行目标路径、近邻与更长路径仍拒绝）；`airwallexLazyLoading.spec.ts` 守卫测试；`auth_login_totp_failclosed_test.go`（#606、#622、#623）

## 升级与兼容说明

- **数据库迁移**：无。
- **登录体验变化**：已绑定认证器的用户，登录后多一步「点『使用认证器验证』再输 6 位码」；没绑认证器的人填错密码不再看到 6 位码框。对 API 响应的结构没有改动（挑战仍与以前同形），自行对接登录接口的客户端不受影响。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 暗色登录页的主按钮本来是药丸，但被全局的 `button` 规则命中成了连续圆角（改动前就是这样）。
- `vendor-misc` 里仍有约 1.4 MB 第三方库（其中 `jsqr` 只被签名分片页用到），拆分要改打包配置和若干页面的静态导入，单独处理。

## 部署

1. 从 Release 下载 `sub2api_2.3.162_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.162，首页注入的 `window.__APP_CONFIG__.version` 也是 2.3.162，页面入口资源哈希与后端一致。
- 登录页：随便填一个邮箱和错误密码点登录——看到提示语和「使用认证器验证」按钮，没有 6 位码框；点按钮后出现码框并已聚焦；改一下邮箱，提示消失。
- 有认证器的账号：正确密码登录后，同样先看到按钮，点后输入动态码能进入。
- 打开仪表盘 / 密钥页 / 登录页，浏览器开发者工具的网络面板里没有 `airwallex.com` 的请求；进入充值里的 Airwallex 支付页，才会出现它们，支付仍能正常拉起。
- 管理员账号绑了 Passkey 且后台模式开启时，密码 + TOTP 之后的 Passkey 步骤不再返回 403（线上没开后台模式时无需验证）。
