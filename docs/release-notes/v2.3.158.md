# v2.3.158

本次为「页面过期强制刷新 + 创建密钥弹窗」体验版本，并带上内容审核自动封禁的安全修复。无数据库迁移，扫链与计费代码无改动。

## 亮点

- **页面过期自动提示并强制刷新**：标签页开着不刷新、前端已经升级时，页面会在几分钟内（或切回标签页时）提示「发现新版本」，下一次页面跳转直接整页刷新；点「创建」密钥时如果页面已过期，弹出不可关闭的「页面已更新，请先刷新」对话框，提交时也再拦一次。只有前端文件真的变了才算过期，纯后端发版不打扰用户；灰度 / 滚动发版期间服务端比页面旧不算过期；过期结果隔 15 秒二次确认才算数；自动刷新有 2 分钟冷却，服务端暂时不一致时不会反复重载。
- **注入页面的版本号补全**：之前服务端注入进 HTML 的 `version` 一直是空串，页面不知道自己是哪个版本，探测会整个不工作；现在和 `/api/v1/settings/public` 的版本一致。**探测只保护这一版之后加载的页面**，更早打开的页面没有这段代码，仍需手动强制刷新一次。
- **旧页面创建密钥失败的提示更清楚**：身份校验未通过（`VERIFY_REQUIRED`）的文案改为中英双语并带强制刷新指引（Ctrl+F5，Mac 用 Cmd+Shift+R）；错误码和 HTTP 状态不变，新页面仍按错误码显示自己的文案。
- **创建密钥弹窗改成和注册页同一套的 Quiet 流程**：「第 N 步 / 共 2 步」加点状进度；第一步只露出名称 / 厂商 / 分组，自定义密钥、IP 限制、额度、速率、并发、过期时间等收进「更多设置」，每次打开都回到收起；页脚左边是安静的文字按钮、右边是胶囊主按钮，按下缩到 0.97。编辑弹窗保持原样。
- **登录密码可由浏览器保存并自动填充**：验证因子里的密码框改为浏览器密码管理器认得的写法（`current-password`，同表单带一个看不见的只读用户名字段）；页面不把密码写进任何 Web 存储，只记住「上次用哪种验证方式」，下次默认选它。
- **内容审核：主开关联动自动封禁**：主开关关闭时自动封禁强制失效（读取、校验、保存、执行四处都生效，保存时会把残留的 `auto_ban_enabled=true` 写回 `false`）；`cyber_policy` 分类缺省不再计入封禁次数（配置里显式写了计入的保持不变）；自动封禁发生时通知管理员（收件人 = ops 告警收件人〔需在后台开启告警邮件〕加工单管理员邮箱，两者都没有时才用首个管理员账号；每小时最多 20 次通知，超出的只记服务端日志；邮件异步发送，失败不影响封禁）。

## 变更清单

### 新增

- 页面版本探测、更新提示条与必须刷新对话框；创建密钥弹窗 Quiet 流程与「更多设置」（#600）
- 内容审核自动封禁时通知管理员（#599）

### 修复

- 注入进 HTML 的版本号一直是空串（#600）
- 内容审核主开关关闭时仍会自动封号；`cyber_policy` 默认计入封禁次数（#599）
- `VERIFY_REQUIRED` 文案对旧页面不友好（#600）

## 升级与兼容说明

- **数据库迁移**：无。
- **内容审核的老配置**：配置由完整序列化写盘，历史配置里已经带着 `cyber_policy_exclude_from_ban_count: false`，会被当作显式「计入」，不会自动换成新默认；要采用新默认，需在后台保存一次，或把该项改成 `true`。升级后核对 `enabled` 与 `auto_ban_enabled` 实际落地的组合；建议在后台「邮件通知」里开启告警邮件并至少配一个收件人（或配置工单管理员邮箱），否则封禁告警只落到服务端日志。
- **日志关键字**：`content_moderation.autoban_forced_off_by_master_switch`（库里存在「主开关关 + 自动封禁开」的组合）、`content_moderation.autoban_applied_admin_alert`（真的封人了，需要人工复核）、`content_moderation.autoban_admin_notify_limited`（通知被限流，说明封禁量异常偏大）。
- **登录密码**：没有按「保存在浏览器本地」字面存进 `localStorage` / `sessionStorage`——这是账号登录密码，放进页面可读的存储里，任何一处 XSS 都能读走。改为交给浏览器自己的密码管理器：第一次输入后浏览器会提示保存，以后自动填好；浏览器关闭了密码保存时不会自动填。
- **页面刷新**：本版发出后，已经打开的旧标签页不会自己提示（旧代码里没有探测），需要用户手动强制刷新一次；从这一版起加载的页面，在下一次前端发版时会自动提示。
- **serverless 节点心跳**：心跳里的 `version` 从空串变成真实版本号，仅用于展示，没有任何比较逻辑。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 二次查看、批量轮换、画布创建里的验证弹窗用的是同一个验证因子组件，已一并获得浏览器自动填充，但没有改成 Quiet 步骤流。
- 页面过期探测依赖入口页面里注入的版本号；没有注入版本号的环境（开发环境、旧后端）里探测不工作，也不会误报。

## 部署

1. 从 Release 下载 `sub2api_2.3.158_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.158，**首页注入的 `window.__APP_CONFIG__.version` 也是 2.3.158**（以前是空串），页面入口资源哈希与后端一致。
- 用户中心 → API 密钥 → 创建：弹窗顶部是「第 1 步 / 共 2 步」，第一步只有名称 / 厂商 / 分组；点「更多设置」展开其它项，关掉再打开回到收起；有验证方式的账号点「下一步」进入第 2 步，输入登录密码并提交后浏览器弹出保存密码的提示，再次打开时密码框被自动填好。
- 用一个没带验证材料的旧页面（或直接调接口）创建密钥：返回 400，`reason` 仍是 `VERIFY_REQUIRED`，`message` 里有强制刷新的指引。
- 后台「内容审核」配置：主开关关闭并保存后，`auto_ban_enabled` 在库里是 `false`；`cyber_policy_exclude_from_ban_count` 的值与预期一致；服务端日志里没有 `content_moderation.autoban_applied_admin_alert`。
