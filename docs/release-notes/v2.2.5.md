# v2.2.5

风控中心的「最后一轮输入」在 `cyber_policy` 记录上一直是空的，前端于是回退显示上游错误，
管理员看到的是一段 "This content was flagged for possible cybersecurity risk..."，
而不是用户真正发出的内容。

## 根因

`RecordCyberPolicyEvent` 只写入了上游错误文本（`error`），从未写入 `input_excerpt`。
前端 `inputDetailText` 的取值顺序是 `input_excerpt || error`，所以空的 `input_excerpt`
会让详情页展示错误 JSON。

## 修复

- `CyberPolicyRecordInput` 新增 `RequestBody`，由网关在记录时带上入站原始请求体。
- `RecordCyberPolicyEvent` 用 `extractCyberPolicyLastUserTurn` 解析最后一轮用户输入，
  写入 `input_excerpt`。
- `contentModerationProtocolForEndpoint` 按端点选择协议：
  `/v1/messages`、`/v1/chat/completions`、`/v1beta/models`、其它按 Responses。
- 覆盖全部四个入口：`/v1/responses`、`/v1/messages`、`/v1/chat/completions`
  以及 WebSocket 每轮（`setCyberTurnBody` 写入的当轮 payload）。
- 只有解析不出用户内容（空 body 等）时，前端才回退显示上游错误。

## 影响范围

- 仅影响风控中心审计记录的展示字段，不改变阻断、计费、封号判定。
- 历史记录不回填：旧行的 `input_excerpt` 仍为空，仍显示上游错误。
