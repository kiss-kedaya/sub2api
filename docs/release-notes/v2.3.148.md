# 2.3.148

## 安全：上游凭据、代理密码与敏感设置改为 at-rest 加密

- **问题**：库里 `accounts.credentials`（5723 行，含上游 api_key / access_token / refresh_token）、`proxies.password`（136 行）、以及 settings 里 OAuth client secret / SMTP 密码 / 验证码密钥等仍是明文，数据库一旦被拖走等于全部凭证泄露。
- **方案**：新增 at-rest 加密层（AES-256-GCM，随机 nonce，`enc:v2:` 封装）；密钥**只来自部署环境变量 `SUB2API_ATREST_KEY`**（`openssl rand -hex 32` 生成），不写入数据库、不写入仓库。
- **兼容与回滚安全**：读路径密文优先、明文兜底；未迁移的行仍保留完整明文，**旧版本二进制可继续工作**；未配置密钥时只读兼容并拒绝加密写入（fail-closed），不会写出无法解密的数据。
- **迁移工具**：`sub2api -atrest-migrate -atrest-tables=accounts,proxies,settings`，默认 dry-run，分批（200 行/批）逐行「加密→解密回读」校验；`-atrest-verify` 只读核对；幂等，失败即停。
- 覆盖的 settings 键：`github_oauth_client_secret`、`google_oauth_client_secret`、`oidc_connect_client_secret`、`smtp_password`、`tencent_captcha_app_secret_key`、`tencent_captcha_cloud_secret_id`、`tencent_captcha_cloud_secret_key`、`turnstile_secret_key`、`notification_email_unsubscribe_secret`。
- 同步适配了所有依赖凭据的 SQL 路径（OAuth refresh 判定、凭据守卫/探测快照、批量更新、模型白名单同步、Codex 导入匹配等），避免迁移后功能失效。

## 说明

- 数据库迁移：`accounts.credentials_cipher`、`proxies.password_cipher` 两列（`334_add_atrest_cipher_columns.sql`），发版前需 `-migrate-only`。
- **上线顺序**：先部署本版本（带 `SUB2API_ATREST_KEY`）→ dry-run 核对 → 执行迁移 → `-atrest-verify` 确认剩余明文 0。
- 回滚：迁移前数据仍为明文，可直接切回 2.3.147；迁移后回滚依赖迁移前的表级备份。
- 密钥不支持轮换（换 key 旧密文不可解），请妥善备份 `SUB2API_ATREST_KEY`。
