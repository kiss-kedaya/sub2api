## 安全修复（紧急，优先上线）

**2FA 登录绕过**：开启 TOTP 的账号可以通过第三方登录直接拿到 token，不校验动态码。

- GitHub / Google 邮箱 OAuth 登录：回调直接签发 access/refresh token，全程未检查 `TotpEnabled`
- 通用 pending OAuth 兑换（LinuxDo / 钉钉 / 微信 / OIDC「已绑定身份登录」）：同样直接签 token
- passkey 登录：不查 TOTP（生产未启用 passkey，属防御纵深）
- step-up 开关读取失败时 fail-open：读库异常会静默关闭二次验证门控

修复方式：统一走 `SettingService.LoginRequiresTOTP`，命中后只下发 `requires_2fa` + 一次性 temp_token，前端回调页输码后经既有 `/auth/login/2fa` 换 token；passkey 与 step-up 开关改为 fail-closed。补「绕不过去 / 正常登录不误伤」两个方向单测。

**管理员 API Key 审计补全**：受限 key 的请求此前只记录通用事件，丢失动作名与参数；已按 key 归属完整记录，认证失败单独留痕，回退开关加启动告警。
