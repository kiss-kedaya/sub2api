# v2.3.170

本次是「用量统计提速 + 管理端安全加固」版本：用量页和管理端的统计在任意时间窗口都能用小时汇总表，不再因为窗口起点不是整点就扫原始日志表；管理端「重置用户 2FA」按独立审计意见加固；登录页新增一个默认关闭的后台开关。**没有数据库迁移，没有计费口径变化。**

## 亮点

- **统计的小时汇总读取不再要求窗口起点整点**（#661）：用量页「按模型 / 趋势 / 分组 / 总览 / 端点分布」和管理端的模型分布、趋势、用户趋势、消费排行，以前只有窗口起点恰好是整点才会读小时汇总表，而「最近 7 天」「本月」「最近 24 小时」这类 `now - N` 的窗口起点几乎永远不是整点，于是每次都扫原始日志表。现在窗口拆成三段：起点到下一个整点的零头读原始表、中间整的已关闭小时读汇总表、开放小时读原始表（头尾和以前的尾部走同一个原始查询，口径一字不差）。汇总缺行、水位过期、覆盖不全时仍然整窗退回原始表。窗口超过 14 天（汇总保留期）、带 Key / 账号 / 分组 / 模型 / 请求类型等过滤条件的查询保持原样。本机用约生产 1/37 的数据对比：重度用户 7 天「按模型」扫描行数 98,701 → 8,422、执行 280 ms → 8.8 ms；全站 14 天趋势扫描 300 万 → 8,316 行、2.35 s → 5 ms（折算到生产为估算，未经生产验证）。差分测试在真实 PostgreSQL 上、3 个时区各 1000 个窗口、共 24,800 次新旧结果比较全部相等。顺带修了一个老问题：整点起点 + 已关闭整点终点的窗口，「端点分布」会按小时返回重复项。
- **管理端「重置用户 2FA」加固**（#660，只有 UID 1 能调用）：重置后撤销该用户全部会话并清空二次验证的尝试预算（以前刷新令牌仍有效、尝试次数仍是 5，忘码的用户重新绑定最长被卡 15 分钟）；读取 Passkey 提前到写库之前，写库之后的善后（撤销 / 发邮件 / 写审计）任何一步失败都不再让请求变成 500，而是在返回体 `incomplete_steps` 里列出；邮件里的「重新绑定」链接改指真实存在的 `/profile`（以前是 404）；**拒绝对自己重置**；这条路由要求 60 秒内刚完成的二次验证（别的路由的 5 分钟窗口不变），并加每管理员每分钟 3 次 / 每小时 20 次的上限；原因入库前做纯文本清洗（含空字符的原因以前会让审计行丢失）；审计里不再存目标用户邮箱明文，改存指纹；邮件正文不再带操作管理员的邮箱；前端弹窗修了错误码读取（以前所有 `RESET_2FA_*` 提示都落到通用文案）。
- **登录首步「伪装二次验证挑战」开关（默认关闭）**（#659）：后台「系统设置 → 安全」新增开关。打开后，凭据无效时下发的二次验证挑战会与真实账号的形状保持一致（真实账号镜像其二次验证方式，其余邮箱按邮箱稳定取形状），减少通过首步响应探测账号二次验证方式的可能。**关闭时登录首步响应与以前逐字节一致**（有测试），回退版本也安全。请在用真实账号逐项验证登录流程（未绑 2FA / 只绑 TOTP / 绑 Passkey 的账号、密码对与错、不存在的邮箱）之后再打开。

## 变更清单

### 新增

- 后台设置 `login_shape_disguise_enabled`（默认关闭）（#659）
- 管理端重置 2FA 接口返回体可选字段 `incomplete_steps`（#660）

### 优化

- 小时汇总读取支持任意起点的窗口，6 个汇总入口全部迁移（#661）
- 管理端重置 2FA：会话撤销与尝试预算清理与命令行共用同一个实现（#660）

### 修复

- 重置用户 2FA 后刷新令牌仍有效、尝试预算不清（#660）
- 读取 Passkey 失败时重置接口返回 500 且半成功（#660）
- 重置邮件里的「重新绑定」链接 404（#660）
- 重置 2FA 的原因含 NUL 等字符导致审计行丢失（#660）
- 重置弹窗读错错误码形状，所有提示落到通用文案（#660）
- 「端点分布」在整点起点 + 已关闭整点终点的窗口里按小时返回重复项（#661）

## 升级与兼容说明

- **数据库迁移**：无。可直接从 2.3.169 蓝绿替换，旧二进制可回退。
- **行为变化（有意的）**：管理端重置用户 2FA 后，目标用户在所有设备上被登出（已签发的访问令牌到期前仍可短暂使用）；管理员确认时需要当场再验一次验证码（60 秒内的授权才放行）；对自己重置返回 400（丢了自己的码请用服务器上的 `-reset-admin-2fa` 命令）；重置邮件的链接与正文有变化；审计 `extra` 里的 `target_user_email` 换成 `target_email_hash`。
- **已知限制**：按 API Key 的用量查询（`/v1/usage`、Key 用量页）没有 Key 维度的汇总，仍读原始表，不受 #661 影响。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
