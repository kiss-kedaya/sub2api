# v2.3.164

本次为「登录页」小版本：登录改成和注册页同一套 Quiet 分步，手机上不再被验证码反复重置卡住，暗色主题下的背景不再持续重绘。无数据库迁移，不改后端接口，扫链代码无改动。

## 亮点

- **登录第二步在同一张卡片里**（#629）：以前点「登录」后，页面会在第一格下面多出一句灰字和一个「使用认证器验证」按钮，再点一下才弹出盖住整页的弹窗。现在和注册页一样：卡片里换成第二步，标题跟着变，显示「第 2 步 / 共 2 步」和点状进度，左下角是「上一步」；旧的一格先退出，再进入新的一格，任何时刻屏幕上只有一格（系统开了「减少动态效果」时直接切换）。绑了验证器的账号密码对了就直接看到 6 格输入框并已聚焦，输满 6 位自动提交。
- **输错密码的人不再迷路**（#629）：服务端对「密码错误」和「需要二次验证」返回同样的响应（防止登录接口被用来探测账号），所以输错密码的人也会先看到第二步。现在第二步里有一行「没有绑定验证器？点这里返回，检查邮箱和密码。」，整行就是返回按钮；返回后光标直接在密码框里、内容已选中，直接重新输入即可。验证码或密码不对时的提示里原来的「取消」也改成了「上一步」。
- **手机上登录不再被验证码卡住、不再弹来弹去**（#629）：以前每次点「登录」（包括已经进入第二步的那次）都会把 Cloudflare 验证码重置一次，小组件回到「正在验证…」转圈，「登录」键灰着，手机上要等它再转完才能点。现在验证码只在需要重来时才重置（登录失败、回到第一步）。提交期间输入框只读而不是禁用（以前会让手机键盘收起、页面跳一下）；邮箱框只在鼠标/触控板设备上自动聚焦，手机进页面不再自动弹键盘。
- **暗色背景不再持续重绘**（#629）：暗色主题下所有认证页的背景网格靠 `background-position` 无限动画，页面空闲时每秒约 100 次整屏重绘（浅色主题 0 次）。改成 `transform` 滑动，触屏设备和「减少动态效果」下完全静止。本地真 Chrome 实测暗色登录页空闲 6 秒：主线程帧 865 → 0（触屏），Paint 1730 → 0，Raster 3460 → 0。

## 变更清单

### 优化

- 登录第二步（认证器验证码 / Passkey）从全屏弹窗改为卡片内的步骤，沿用注册页的步骤头、上一步和先退后进的过渡（#629）
- 登录页验证码只在登录失败、回到第一步时重置；拿到第二步挑战和登录成功跳转前不再重置；第二步期间验证码过期不再弹提示（#629）
- 认证页暗色背景网格改为合成层动画，触屏设备静止（#629）
- 验证码输入框去掉浏览器自带的整行黑框（六个格子自己已画焦点环）（#629）
- 卡片和步骤面板入场动画 `fill-mode` 改为 `backwards`，动画结束后不再常驻 `transform`（#629）

### 修复

- 输错密码后第二步没有任何出口提示（#629）

### 测试

- `LoginView.dualFactor.spec.ts` 重写为 28 条（卡片内第二步、返回与光标、验证码重置时机、输入框只读、初始焦点、两格先退后进、退出中取消）；对登录页做了 20 处变异检查，全部被测试发现；整套前端 5256 条通过（#629）

## 升级与兼容说明

- **数据库迁移**：无。
- **接口**：登录相关接口、响应结构和防枚举行为均未改动，自行对接登录接口的客户端不受影响。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **组件改名**：`TotpLoginModal` → `TotpFactorPane`、`PasskeyLoginModal` → `PasskeyFactorPane`（它们不再是弹窗），仅影响二次开发。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 手机上「一直闪烁」是用户反馈，我们在无头 Chrome 的手机视口里没能复现持续闪烁；本版修掉的是能量出来的成因（暗色背景持续重绘、验证码被反复重置、键盘被收起、全屏弹窗、动画结束后常驻 transform）。如果在真机上仍然闪烁，请反馈手机型号、浏览器和浅色/深色主题。
- Cloudflare 验证码本身卡在「正在验证…」（网络或浏览器隐私设置导致）不在本版处理范围。
- 系统偏好为深色的访客，在页面加载完成前看到的仍是白底（原来就是这样）。

## 部署

1. 从 Release 下载 `sub2api_2.3.164_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.164，首页注入的 `window.__APP_CONFIG__.version` 也是 2.3.164，页面入口资源哈希与后端一致。
- 登录页随便填一个邮箱和错误密码点「登录」：卡片平滑换成「第 2 步 / 共 2 步」，下面有一行「没有绑定验证器？点这里返回…」，点它回到第一步，光标在密码框里、内容已选中；整个过程验证码小组件不会回到「正在验证…」。
- 用一个**绑了验证器**的账号登录：密码后直接是 6 格输入框并已聚焦，输满 6 位自动提交并进入控制台。用一个**没绑**的账号登录：直接进入控制台。
- 绑了 Passkey 的账号：密码后是「验证 Passkey」一步，点按钮完成验证。
- 手机（或浏览器手机模式）打开登录页：不会自动弹出键盘；深色主题下页面静止不闪。
- 开发者工具 Network：点「登录」后验证码小组件不再重新请求验证。
