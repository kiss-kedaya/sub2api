# 2.3.151

## 新增：2FA 5 分钟免重复验证凭证

- 输一次 2FA 验证码后，服务端下发 **5 分钟有效的不透明凭证**（HttpOnly + Secure + SameSite=Lax Cookie，body 不回显）：
  - 5 分钟内**校验密码**（改密码、绑定/更换登录邮箱）不再要求 2FA；
  - 5 分钟内**重新登录**（同浏览器、同 IP、同 UA）不再要求二次验证。
- 安全设计：
  - Cookie 内只有 32 字节随机串；Redis 只存其 SHA-256，TTL 300s；
  - 绑定 用户 ID + 可信代理解析的客户端 IP 哈希 + UA 哈希，任一不匹配即失效；
  - 固定 5 分钟绝对窗口，使用后最多重签一次且不延长到期；
  - 校验 10 次/分钟限流；Redis 不可用时 **fail-closed**（强制 TOTP）；
  - 改密码、关闭/重置 2FA、管理员改密/启停/改角色/删号、撤销会话、登出 → 立即删除该用户全部凭证；
  - 签发/使用/拒绝全部写审计，不记录凭证、验证码、密码。
- 无数据库迁移（状态全在 Redis）。

## 修复：管理端建号与改邮箱补齐 step-up 门控

- **建号**（`POST /api/v1/admin/users`）：纳入 step-up；请求体带非零 `balance` 或 `allowed_groups` 时强制二次验证；服务端拒绝在建号时直接写余额（余额调整走带流水与审计的专用接口）。
- **改邮箱**（`PUT /api/v1/admin/users/:id`）：普通用户账号的邮箱变更同样要求 step-up，切断「改邮箱 → 忘记密码 → 接管账号」链路。
- 这两处是近版本安全审计发现的高危缺口（可凭空造钱 / 可接管普通用户），修复后回归测试覆盖 403/200/参数校验矩阵。
