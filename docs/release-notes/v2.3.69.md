# Sub2API 2.3.69

## 扫链：节点限流不再白丢一个周期

- 扫链遇到节点限流（HTTP/RPC 429）时，原来整轮直接失败、链游标不动，下一轮又是同样的突发，链上积压永远追不平。
- 现在 `scanAll` 判到 429 会退避 3 秒再跑一轮，仍失败才按原样上报。只对 429 生效，其它错误仍是一次即报。

## 运维提示

- BSC 至少配 3 个以上支持 `eth_getLogs` 的节点；实测 `bsc-dataseed.binance.org`、`1rpc.io`、`ankr`、`drpc` 都不支持该接口，`bsc.publicnode.com` 可用。
- 单轮 `scan_range` 建议 200~300，太大跨度会让 `eth_getLogs` 单次响应过大而失败。
- 通过后台保存配置会覆盖直接改库的节点列表，改完请在后台页面确认。
