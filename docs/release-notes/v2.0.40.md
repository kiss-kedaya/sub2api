本版把上次同步之后上游新增的功能逐个手工搬进来。二开的计费、选号、鉴权、支付没有被覆盖。在途预留是新能力，默认关闭，生产行为不变。

## 新增

- **GPT-6.1 Sol 支持。** 模型识别、计费兜底价、Codex 离线清单、思考档都按官方口径接入。GPT-6 家族的 `reasoning.mode` 与 `reasoning.effort` 分开处理，开启思考时去掉 temperature 等采样参数。
- **Astra Ultrafast。** Astra 的 Ultrafast 档按官方 6 倍计，Opus 5.5 没配 Fast 倍率时按 2 倍。GPT-6.1 的离线模型清单改用官方完整描述符。
- **Codex 客户端配置支持远程模型目录。** 后台生成的 Codex 配置默认写远程目录地址，清单超过 1MB 或手动选择文件模式时才写本地文件路径。
- **Claude 原生重置额度。** 账号页可以按需查询 Claude 原生重置额度，确认后兑换。同一只号重复提交走幂等，不会重复扣。返回前去掉上游的授权和组织标识。
- **余额模式在途预留（默认关闭）。** 开启后，准入时按估算费用在 Redis 里占住余额，防止并发请求看到同一份余额集体透支。请求进行中每 ttl/3 续期，请求结束后保持到异步计费扣完余额缓存再释放，计费任务卡住时最多一个 TTL 后自动失效。估算失败或 Redis 不可用时放行，退回原来的余额检查。

## 修复

- **前端 Axios 升到 1.20.0。** 修前端安全审计报的 Axios 版本问题。
- **Grok CLI 身份头。** 按正常交互式 CLI 的抓包修正出站身份头。
- **API Key 创建限制。** 增加创建数量与频率限制，默认每小时 60 次。

## 配置变更

- 新增 `billing.inflight_reservation`，`enabled` 默认 `false`。其余字段（ttl、token 上限、金额上限）只在打开后生效。生产环境不需要改配置。

## 升级注意

- **数据库迁移：无。**
- 在途预留默认关闭，不打开时计费行为与 2.0.39 一致。
- 前端有变化（Codex 配置、账号页重置额度按钮），需要重新构建前端。
- 按滚动方式部署：逐个实例换二进制并确认监听后，再切换下一台。
