# v2.3.171

本次是「网关热路径提速」版本：OpenAI 兼容入口不再对同一份请求体反复整体扫描，`GET /v1/usage` 这类客户端高频轮询的按 Key 聚合也不再每次都重新扫一遍用量表。**没有数据库迁移，没有计费口径变化。**

## 亮点

- **请求体顶层字段改成「扫一次、查多次」**（#655）：一个请求在进入网关到转发给上游的路上，会向请求体问几十次顶层字段（`stream`、`service_tier`、`reasoning.effort`、`max_output_tokens`、`tools`、`input`……），每一次 `gjson.GetBytes` 都从头扫整份请求体，遇到 `input` / `messages` / `tools` 这类大字段还要整段跳过。生产 30 秒 CPU profile 里，这类整体重扫占网关 CPU 的 30%~36%。现在为每个请求（请求体 ≥ 16KB 时）建一个惰性的顶层索引：第一次查询只扫到能回答它的那个成员为止，后面的查询复用已扫部分、从断点继续，任何单次查询都不会比原来读得更多、同一字节也不会读两遍。**输出与原来的 gjson 调用逐值一致**（类型、原文、字符串值、数字、偏移）：拿不准的情况（请求体顶层不是严格合法的 JSON、顶层 key 含转义、路径不是普通 key、嵌套对象过大等）一律整体退回原来的 gjson 调用，行为就是旧行为。迁移了 OpenAI 兼容入口（Responses / Chat Completions / Messages 桥接）上 19 类调用点；Anthropic 入口、WebSocket 连接上的请求、小于 16KB 的请求体保持原路径。本机基准：一个请求触发的那串顶层查询，41KB~1MB 请求体上快 13~16 倍，迁移后的真实函数链快约 43%（本机数字，生产收益未经验证，上线后以同样的 CPU profile 复测）。验证方式：23 个调用点各 25,000 个随机请求体、21 个 service 函数各 25,000 个随机请求体、Codex 形状的 20KB~400KB 大请求体，新旧输出逐项相等；对索引做了变异检验；独立审计（对抗输入、缓存失效、并发、变异）提出的 5 条全部处理并补了回归测试。
- **`GET /v1/usage` 按 Key 聚合不再每次轮询都扫用量表**（#664）：CC Switch 等客户端工具每隔几秒到一分钟轮询 `GET /v1/usage`，生产上两台网关合计约 217 次/分钟，每次都要为这个 Key 重新聚合 30 天的「按模型」和「按日趋势」，一个重度 Key 在保留期内有几百万行，库上常驻约 3 个这样的重查询、每个几秒。缓存几乎不命中：默认 30 天窗口的起止每分钟换一次（缓存键里带窗口，下一分钟必然是新键），缓存 TTL 60 秒又约等于轮询间隔。现在：没带 `start_date` / `end_date` 时默认窗口对齐到 5 分钟（同一个 5 分钟内问的是同一个问题）；按 Key 且窗口超过一个自然日的聚合（按模型、按日趋势、Key 汇总：`/v1/usage`、`/v1/sub2api/usage`、Key 用量页）缓存 5 分钟（常量，不新增配置；已配置更长的 TTL 不会被缩短）。失败、超时、取消的结果仍然不进缓存。顺带修了一处：按日趋势的缓存键补上了时区（日标签按数据库会话时区切，换时区就是另一个答案）。
- **测试稳定性**（#663）：一个按「内存分配次数 / 字节数」做上界断言的测试，因为统计的是整个进程的分配，会被同包其他测试遗留的后台协程污染而偶发误报（CI 上出现过 66 次 > 40）；改为取 5 次测量的最小值，阈值和被测代码不变。只改测试文件。

## 变更清单

### 优化

- 请求体顶层字段按请求惰性建索引，OpenAI 兼容入口 19 类调用点迁移，拿不准整体退回 gjson（#655）
- `GET /v1/usage` 默认窗口按 5 分钟对齐；按 Key 的多日聚合缓存 5 分钟（#664）

### 修复

- 按日趋势的缓存键缺少时区（#664）
- 分配断言测试被同包后台协程污染而偶发失败（#663）

## 升级与兼容说明

- **数据库迁移**：无。可直接从 2.3.170 蓝绿替换，旧二进制可回退。
- **行为变化（有意的）**：按 Key 的用量报表（`GET /v1/usage` 的「按模型」、按日趋势，Key 用量页的多日汇总）最多滞后 5 分钟；今日 / 累计看板和之前一样最多滞后 60 秒（本版未改）。带显式 `start_date` / `end_date` 的整天窗口边界不变。
- **已知限制**：用量表本身的读放大没有改变，只是少扫了；按 Key 的用量没有 Key 维度的小时汇总（那需要迁移，另议），首次（缓存未命中）的聚合仍然是几秒量级。
- **回退**：回退到 2.3.170 即恢复旧行为；缓存键里补了时区，蓝绿切换期间新旧版本各用各的键，不会串。
- **页面刷新**：本版没有前端改动。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
