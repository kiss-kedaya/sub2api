# v2.3.167

本次是「稳定性 + 计费 + 路由」版本：修掉高并发下热点账号每个响应都同步写两次数据库、把数据库连接占满后出现的「503 Billing service temporarily unavailable」；Claude 违规拒答恢复按上游规则正常计费（用量里保留「Claude违规拒答」标记）；智能路由按综合评分选组并把会话粘住；分组可单独设置 Fast / UltraFast 档位倍率；用户用量页聚合和诊断写入也减了数据库压力。含 3 个数据库迁移（340、341、342），不改扫链代码。

> 2.3.165 没有上线（它的迁移 340 在同一个事务里先后给 `groups` 和 `usage_logs` 加列，遇到「先读 usage_logs 再关联 groups」的看板查询时被数据库判为死锁、整体回滚）。2.3.166 的违规拒答计费口径有误（把拒答计为 0 费用，而上游对拒答照常收费），本版已更正；已打开 2.3.165 / 2.3.166 的请直接使用本版。

## 亮点

- **修复高并发下的 503「Billing service temporarily unavailable」**（#650）：Anthropic 账号每个成功响应都会把同一行账号数据写两次（5 小时窗口状态 + 被动用量采样），而且是在写响应头之前同步完成。热点账号上这两次写被行锁排成一长队，每个排队的请求占住一个数据库连接，连接池被占满后，别的请求连余额校验都拿不到连接，就报 503。现在按账号去抖（内容没变化最多每 60 秒写一次，utilization 变化不足 1 个百分点也不写），真要写的内容放到后台有界异步执行（同账号同时只有一个在途写、全局最多 16 个、单次 3 秒超时、满了直接丢弃下次再试），请求路径上只剩一次内存查找，不再等数据库。窗口重置、429 限流、写失败都会强制重写，数据口径不变。
- **Claude 违规拒答恢复正常计费，用量里保留标记**（#647）：上游对「200 + 无内容 + stop_reason=refusal」的请求照常收费，所以网关和普通请求走同一条计费路径（余额 / 订阅 / Key 额度 / 账号额度 / 账号统计成本全部照常），只在用量记录上保留「Claude违规拒答」类型，可按类型筛选；返回给客户端的响应仍是上游原样。
- **智能路由按综合评分选组，会话粘在所选分组上**（#633）：Key 里同一个模型有多个分组时，新会话按「成功率 30%、缓存率 20%、首字时间 10%、倍率 20%、你排的优先级 20%」打分选组，分差不到 0.02 算平手、按你排的顺序。会话一旦被某个分组服务就粘在它上面，之后每次先走它，缓存不再因为换组反复重建；只有该分组这次取不到可用账号、这次请求已经出过上游错误、或监控显示该分组成功率低于 50% 时才重新判断并改绑。授权、模型白名单、渠道映射、计费准入仍逐分组校验，粘住的分组被收回授权后不会继续被用。
- **分组可单独设置 Fast / UltraFast 档位倍率**（#635、#634）：分组设置里新增两个输入框，倍率叠加在分组原有倍率上（不是独立倍率）。留空 = 官方档位价（Fast 通常 2 倍、GPT-5.5 为 2.5 倍，UltraFast 6 倍）；填 1 = 不加价（免费 Fast / 免费 UltraFast）；也可以填别的数。原来的「免费 Fast」开关等价于 Fast 倍率 1，行为不变。用量明细的费用气泡新增「档位倍率」「综合倍率」。
- **修复：强制 Fast 开了、免费 Fast 却还按 Fast 价扣**（#635）：管理员刚改完分组，强制 Fast 立刻生效，但计费读的是进程内的分组缓存，最长 10 分钟才刷新，期间请求被强制成 Fast 却仍按旧的「免费 Fast=关」计费。现在计费用请求当时、与强制 Fast 同一份分组数据；进程内分组缓存由 10 分钟缩到 30 秒，改分组倍率 / 策略最多 30 秒内在所有实例生效。
- **用户用量页的聚合查询不再互相拖垮数据库**（#645）：用户 / Key 的用量聚合（按模型、按日趋势、概览）原来每次未命中缓存都直接扫库，并发刷新时会占满数据库。现在每个进程同时在库上跑的聚合最多 8 个，多出的排队，拿不到名额返回 503 `USAGE_STATS_BUSY`（前端刷新即可）；调用方取消不再记成失败，超时失败记 30 秒避免反复重跑；`request_id` 不再拆缓存键；Key 列表的 24 小时概览改走缓存。配置项 `usage_stats_cache.max_concurrent_loads`（0 = 关闭闸）。
- **连接诊断写入批量化、异步提交**（#644）：连接 trace 由「一条请求一个事务一次 fsync」改为一个事务最多 256 条、最多等 20 毫秒；队列由 256 扩到 4096，仍然非阻塞，满了才丢并限频记录丢弃数；停机时会把队列冲刷完。诊断类写入用异步提交（只影响这类写入，计费、余额、用量日志不受影响），数据库崩溃时最多丢最后几百毫秒的诊断记录。
- **修复：compact-2026-01-12 beta 也授权 context_management**（#643）：之前只带这个 beta 头的请求会丢掉 context_management，导致上下文压缩（compaction）失效，现在恢复。
- **错误信息里 Anthropic 官方参数名不再被误打码**（#632）：例如 `thinking.type.enabled` 以前会被当成域名替换成 [redacted]，客户端看不懂报错；真正的上游域名、内网地址、凭据仍然会被清除。
- **带签名的历史 thinking 块原样交给上游验签**（#631）：以前请求没带顶层 thinking 参数时会悄悄删掉历史里的 thinking 块，把上游本该返回的「签名无效」400 变成 200；现在非空且非占位的签名保留，缺失或空签名仍然剥离（兼容 Claude Code 回传历史不带签名的情况）。
- **管理员恢复手段**（#641、#642）：服务器上的恢复命令 `sub2api -reset-admin-2fa -user-id <ID> -confirm` 新增显式开关 `-clear-admin-passkeys`，同一个数据库事务里重置 TOTP 并删除该管理员的全部 Passkey，任何一步失败整体回滚，提交后撤销该管理员的会话和二次验证授权；管理端新增「破玻璃重置用户 2FA」接口（原因必填、写审计、发邮件通知、需要 step-up 验证）。

## 变更清单

### 新增

- 恢复命令开关 `-clear-admin-passkeys`（#641）；管理端破玻璃重置用户 2FA（#642）
- 分组 `openai_fast_multiplier`、`openai_ultrafast_multiplier`（管理端接口与分组表单）；用量日志 `service_tier_multiplier`（用户端、管理端用量接口都会返回）（#635、#634）
- 用量类型 `claude_refusal`（用量筛选、类型徽章、中英文文案）（#637）
- 配置项 `usage_stats_cache.max_concurrent_loads`（#645）

### 优化

- Anthropic 账号窗口状态与被动用量采样：按账号去抖 + 后台有界异步落库（#650）
- 用户 / Key 用量聚合：并发闸、失败记忆、缓存键归一、Key 列表 24 小时概览走缓存（#645）
- 连接 trace 批量写入、诊断写入异步提交、停机冲刷（#644）
- 智能路由评分只调整尝试顺序，不绕过任何校验；Redis 读写限 50ms，出错或没有会话标识时退回纯评分选组（#633）
- 调度器分组缓存 TTL 10 分钟 → 30 秒（#635）

### 修复

- 高并发下热点账号每响应同步写库，占满连接池后出现 503 Billing service temporarily unavailable（#650）
- Claude 违规拒答计费口径：恢复正常计费并保留类型标记（#647）
- compact-2026-01-12 beta 不授权 context_management，压缩失效（#643）
- 强制 Fast + 免费 Fast 同时开时仍按 Fast 价计费（#635）
- 改分组倍率后几分钟内部分请求仍按旧倍率计费（#635）
- 错误信息里的 Anthropic 官方参数路径被误打码（#632）
- 历史 thinking 块带非法签名时上游 400 被预过滤吞掉（#631）

## 升级与兼容说明

- **数据库迁移**：340（groups 增加两个可空列，只碰 groups）、341（放宽 usage_logs 的 request_type 约束，`NOT VALID`，不扫全表）、342（usage_logs 增加一个可空列，只碰 usage_logs）。每个迁移只锁一张表，避免和看板的关联查询互相等待。三个迁移都自带 `SET LOCAL lock_timeout = '5s'`：这些 ALTER 要 usage_logs / groups 的排他锁，数据库默认没有锁等待上限，拿锁期间这两张表上的新查询会全部排队；现在拿不到锁就整个迁移回滚、发版在换二进制之前中止（线上实例不受影响），隔几秒重试即可。从已经应用过 340–342 的库升级时没有待执行迁移；旧二进制不读新列，可回退。
- **接口**：分组对象新增 `openai_fast_multiplier`、`openai_ultrafast_multiplier`（仅管理端）；用量日志新增 `service_tier_multiplier`、`request_type` 新增取值 `claude_refusal`，旧客户端忽略多出的字段即可；用户用量统计接口在数据库繁忙时可能返回 503 `USAGE_STATS_BUSY`，刷新即可。
- **行为变化**：Anthropic 账号的 5 小时窗口状态和被动用量（后台账号用量条）现在最多落后 60 秒；调度阈值读到的被动用量同样最多落后这么久。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
