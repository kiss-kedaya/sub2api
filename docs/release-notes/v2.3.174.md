# v2.3.174

本次是「再降库压力 + 一处防御性修复」版本：按 API Key 的「按日趋势」不再每隔一段时间就把整个窗口（含不会再变的历史）重扫一遍；渠道监控的历史回填补上一处只有运维重置游标或蓝绿期间有落后进程时才会触发的数据保护。**没有数据库迁移，没有计费口径变化，没有前端改动。**

## 亮点

- **按 Key 的「按日趋势」拆成「已关闭的天 + 今天」两段**（#673）：2.3.172 上线后的稳态实测（11 分钟的慢语句日志，≥2.5 秒）里，按 Key 的按日趋势占全部慢语句数据库时间的约 54%（20 条、205 秒，平均 10.2 秒、最长 22.7 秒，涉及 18 个不同的 Key）：它的窗口是用户时区午夜对齐的 30～90 天（用量表实际只保留 15 天），而已关闭的天只会因极少数迟到行或手工改写而变，却被每 15 分钟整段重扫一遍。本版对「按 Key、按日粒度、窗口超过 25 小时、窗口里既有已关闭的天又有今天」的查询，在窗口所在时区「今天的本地午夜」（按时区算本地午夜，不是「结束时间减 24 小时」，夏令时当天是 23 / 25 小时）把窗口拆成两段，各自走缓存：
  - **已关闭的天**缓存 26 小时（仍按「按 Key 多日聚合」类处理：28 秒加载预算、超时记忆 5 分钟）；缓存键带着窗口起止，每个本地午夜自然换新，不需要手动失效；
  - **今天**用缓存默认时长（默认 60 秒，运维可用 `usage_stats_cache.ttl` 调），单次只扫当天已有的行；
  - 两段结果**按日标签求和**合并（窗口按用户时区切、日标签按数据库会话时区切，两者不同时同一个日标签可能同时出现在两段里）；任一段失败整次调用失败，不返回半截数据；没有配置缓存时不拆。
  - 效果：「今天」那根柱子最多滞后 60 秒（以前最多 15 分钟）。慢语句日志里 `key_daily` 的总时间预期降到现在的 1/5 以下；总读量取决于轮询频率：每 10 分钟轮询一次的 Key 约降到 1/12，每分钟都轮询的重 Key 因为今天段每分钟刷新只降约一半（**均为估算，上线后以慢语句日志复测**）。
  - 验证：在真实 PostgreSQL 上做了差分测试，1247 个窗口 × 3 个标签时区共 3741 次「拆开合并」与「不拆的直接查询」逐点相等，覆盖夏令时切换日（洛杉矶、伦敦、悉尼、Lord Howe 半小时夏令时）、半小时时区（加尔各答、加德满都）、窗口时区与库会话时区错位、本地午夜前后 ±1 微秒；变异检验改坏切点、求和、两段缓存时长共 13 处，测试全部变红。
- **渠道监控历史回填的游标跟上数据库里更早的游标**（#672，防御性修复，线上现状不触发）：2.3.173 起，稳态保留期清理读数据库里的回填游标判断历史回填是否走完；而回填读的是进程内存里只在启动时读过一次的游标。两个实例同时在跑（蓝绿期间 / 多实例）时，先走完的实例让库游标越过 90 天边缘、清理开始以后，落后的实例仍会对已被清理的区间重放，把 12 小时汇总重建成残缺值（审计实测 144 变 21），整天对齐的回放还会删掉已有的 1 天汇总行。生产的历史回填早已走完，所有进程启动时读到的都是完成态，所以现状不触发；触发条件是运维重置游标，或某个进程落后 15 小时以上。现在每个 tick 重读水位时同时采纳「更早」的库游标（回填只会往更早走），库游标为空或更晚时保持不变。

## 变更清单

### 优化

- 按 Key 的按日趋势拆成「已关闭的天（缓存 26 小时）+ 今天（缓存默认时长）」两段（#673）

### 修复

- 历史回填的内存游标不跟随库里更早的游标，落后进程可能对已清理区间重放（#672，防御性）

## 升级与兼容说明

- **数据库迁移**：无。可直接从 2.3.173 蓝绿替换，旧二进制可回退。
- **行为变化（有意的）**：
  - 按 Key 的按日趋势里「今天」那一点最多滞后 60 秒（2.3.172 / 2.3.173 是最多 15 分钟）。
  - 已关闭的天最多滞后一整天：迟到的用量行、手工改写的历史用量，要到次日本地午夜缓存换键之后才反映到「按 Key 的按日趋势」里；不影响余额、计费，也不影响 `/v1/usage` 的汇总和按模型报表。午夜后几秒内才落库、`created_at` 在午夜前的行，也要到次日才算进昨天（正常落库延迟是毫秒到秒级）。
  - 每个本地午夜之后的第一次轮询，所有活跃 Key 的已关闭段会同时未命中（缓存键换了）：每个 Key 一次，成本约等于之前 15 分钟一次的单次整窗口扫描，全天只一次，之后一整天命中；并发仍受用量聚合并发闸约束；用户时区不同的 Key 午夜不同，天然错开。
  - 缓存（Redis）不可用时，每次调用是 2 条语句而不是 1 条（读的行总数不变）。
- **已知限制**：
  - `GET /v1/usage` 自己仍只等 2 秒预算：今天段每分钟读一次，最重的 Key 的今天段如果超过 2 秒，那次响应缺 `daily_usage`，下一次轮询补上（加载在后台继续并写缓存）。
  - 单次扫描仍超过 28 秒的重 Key 的已关闭段仍会失败，只是每 5 分钟才重试一次；要从根上解决需要按 Key 维度的小时汇总（要迁移，另议）。
  - 按 Key 的「按模型」报表（`/v1/usage` 的 `model_stats`）本版没有改动，仍是 15 分钟网格 + 15 分钟缓存。
- **回退**：回退到 2.3.173 即恢复整窗口单次查询（15 分钟缓存）；缓存键包含窗口起止与缓存类别，蓝绿期间新旧版本各用各的键，不会串。
- **页面刷新**：本版没有前端改动。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
