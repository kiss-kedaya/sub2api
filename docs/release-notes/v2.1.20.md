# v2.1.20

安全加固版本，全部为出站请求与计费准入的缺陷修复，无迁移、不改价格/倍率/预扣。

## 出站 SSRF

- **SMTP 测试端点**：`/admin/settings/test-smtp` 与 `/send-test-email` 过去按请求里的
  `smtp_host/smtp_port` 直接拨号，并把 `read tcp <源端口>-><目标>: i/o timeout` /
  `connection refused` 原样回给调用方——等于一个任意 host:port 的 TCP 端口预言机。
  现在所有 SMTP 拨号都经 `Control` 回调在 connect 前校验目标，拒绝回环/RFC1918/
  link-local/云元数据（含 DNS rebinding），隐式 TLS 走同一 dialer，策略拒绝不再
  回落明文重拨。对外只返回固定文案，细节只进服务端日志。
- **CRS 同步/预览**：`base_url` 由管理员手填且 `AllowPrivateHosts` 默认为 true，
  可对任意内网主机发 `POST /web/auth/login` 与 `GET /admin/sync/export-accounts`，
  并把 `status=%d body=%s` 回显。现在 CRS 目标恒做解析 IP 校验，内网目标只有在
  `crs_hosts` 白名单显式列出时才允许；上游响应只进日志。
- **账号测试 / 上游计费探测**：`/admin/accounts/:id/test` 与
  `/upstream-billing-probe` 使用账号 `credentials.base_url` 出站，allowlist 关闭时
  `validateUpstreamBaseURL` 只剩格式校验，可拨回环/Docker 网桥，并把对方响应体
  回显到 SSE 且落库到 `error_message`。现在无论 allowlist 开关如何都拒绝私网目标。

## 计费准入

- **在途预留低估约 50×**：预留输入只按 `bodyBytes/4` 估算，而上游 Codex/Responses
  渠道会在客户端 body 之外注入约 4.4k 上下文（实测 99B 请求结算 `prompt_tokens=4387`），
  导致小额余额并发时准入形同虚设（实测 8 并发把余额打成 4.79 倍透支）。
  新增 `billing.inflight_reservation.min_input_tokens`（默认 4096）作为输入估算下限；
  另增 `fail_closed_on_reserve_error`，可选把「余额读取/Redis 失败」从放行改为拒绝
  （默认 false，保持旧行为）。

## 前端

- **embed URL 不再向第三方域发送 access JWT**：`buildEmbeddedUrl` 只在同源或
  `VITE_EMBEDDED_TRUSTED_ORIGINS` 白名单命中时才附加 `token`；第三方嵌入方仍能拿到
  `user_id` / `theme` / `lang` / `ui_mode`，但拿不到凭据。
