# v2.3.155

本次为安全加固与稳定性版本：充值扫链在公共 RPC 限流下自愈、API Key 身份校验补口（限流 / 密码失败预算 / 动态码一次性）、网关路径别名的预认证开销封顶、破玻璃重置 2FA 真正撤销授权、依赖漏洞升级。无数据库迁移。

## 亮点

- **充值扫链自愈**：免费公共 RPC 限流 / 额度耗尽时，Polygon 等链的扫描游标不再一停就是几小时。节点池记住各节点自己说出的 `eth_getLogs` 区块上限并绕开，额度 / 余额用尽的节点长冷却，健康状态跨轮共享；前向扫描连续停滞时按 5s → 60s 退避（head 观察与待入账不受影响）；一个区间里失败的地址批次在同一次扫描内只重跑失败的批次（≤3 轮、每轮并发减半）；空闲链钱包守卫改用独立的 advisory lock、按链各自退避、每链独立时间片，不再长期占用充值扫描的锁。这组改动已先以侧车热修 `v2.3.148-bsc5` / `bsc6` 在线上验证。
- **API Key 身份校验补口**：单条轮换、批量轮换、封存（`PUT secret-seal`）补上按用户限流（创建 / 轮换 / 批量轮换 / 二次查看授权 / Passkey 校验共用每用户每分钟 10 次，只有带 `regenerate_key=true` 的编辑才计数；封存每用户每分钟 60 次）；登录密码因子增加按用户的失败预算（60 秒内最多 5 次错误，成功清零，预算用尽返回 `429 VERIFY_PASSWORD_RATE_LIMITED` + `Retry-After`，与 2FA 计数互不影响）；身份校验里的动态码改为一次性；「是否设置过登录密码」按真实的本地密码判断（OAuth 注册后又设置了密码的用户恢复密码因子）；封存 PUT 的旧客户端兼容分支不再无校验。
- **路径别名加固**：版本段超过 16 个的路径原样透传，不再有预认证的二次方开销（8KB 路径约 0.4s CPU → 微秒级）；折叠后仍不存在的 `/v1/v1/*` 路径回到 gin 链内产生 404 诊断，Honeypot / IP 风险检查 / Recovery 对它们照常生效；别名索引只收网关族路由，管理面板路径（如 `/api/admin/usage`）不再被别名到面板路由。
- **破玻璃重置 2FA 真正撤销授权**：`-reset-admin-2fa` 现在按因子（TOTP / Passkey）与会话枚举并撤销 step-up 授权（此前只删旧布局的键，命令行却提示「已撤销」）；Passkey 的两个 `finish` 接口的请求体不再进入审计日志。
- **依赖漏洞**：`gorilla/websocket`（GO-2026-6278）与 `go.opentelemetry.io/otel` 系列（GO-2026-6974 / 6975）升级到修复版本，CI 的 Security Scan 恢复绿色。

## 变更清单

### 修复

- 充值扫链：公共 RPC 限流 / 额度下反复卡死（区间上限学习、逐链退避、守卫独立锁、失败批次重跑）（#585）
- 依赖：otel v1.47.0、gorilla/websocket 修复提交（#586）
- 网关路径别名加固：超多版本段 DoS、未命中诊断回到 gin 链内、别名索引只收网关族路由（#587）
- 破玻璃重置 2FA 撤销全部因子的 step-up 授权；Passkey finish 请求体不入审计库（#588）
- API Key 身份校验加固：轮换 / 封存补限流、密码失败预算、动态码一次性、本地密码判断（#589）

## 升级与兼容说明

- **数据库迁移**：无。
- **新增限流与失败预算**：脚本批量轮换 Key 的客户端会看到新的 `429`（带 `Retry-After`）；输错登录密码连续 5 次后 60 秒内返回 `VERIFY_PASSWORD_RATE_LIMITED`（猜对也一样，60 秒后自愈）。用密码或动态码校验时，创建 / 轮换 / 二次查看授权共用每用户每分钟 10 次；**用 Passkey 校验时每把轮换占 3 次额度（begin / finish / 提交），一分钟最多连续轮换 3 把**，超出等最长 60 秒。批量轮换一次请求只算 1 次；批量轮换后逐把封存最多 50 次不会触顶（封存单独 60 次/分钟，输对密码会清零失败预算）。
- **封存旧分支**：停留在 **2.3.153 或更早版本**页面上的标签页，对有因子的账号做「以后可查看」封存会失败（那些页面的封存请求不带密码与授权因子）；2.3.154 的页面不受影响，刷新后正常，不会覆盖已有密文。
- **界面文案如实表述**：「以后可查看」的勾选提示与查看弹窗原写「密码不会发送到服务器」，与实现不符——封存请求会带登录密码给服务端做一次 bcrypt 校验（校验后丢弃、不保存，审计也不记该请求体）；两条文案已改为如实表述。
- **动态码一次性**：同一个 TOTP 码不能再重复用于下发明文，也不能与登录共用；创建 Key 走幂等时，重放同一个 `Idempotency-Key` 需要重新校验（TOTP 账号要换新码）。
- **路径别名**：版本段超过 16 个的路径不再被折叠（本来也不是合法写法）；管理面板路径不再被别名到面板路由；`/v1/v1/*` 的诊断 404 现在先经过 Honeypot / IP 风险检查。
- **依赖**：`gorilla/websocket` 升到上游修复提交（上游暂无正式 tag）。
- **crypto 侧车**（`CRYPTO_INSTANCE_ENABLED=true` 的那个实例）换成本版即可，扫链行为与热修 `v2.3.148-bsc6` 一致；回滚点是 `v2.3.148-bsc6`。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 面板级 429（响应体只有 `RATE_LIMITED`）在轮换、封存、Passkey 完成步骤、无限画布里显示为泛化失败，没有「请 N 秒后重试」的提示。
- 重放同一个动态码也会消耗 TOTP 失败预算（5 次 / 15 分钟）：连续 5 次复用刚用过的码会锁 TOTP 校验 15 分钟，界面提示里没有锁定说明。
- 重置过密码的第三方注册用户没有「已设置本地密码」的痕迹，仍按「不知道密码」处理（只是少一个可选因子，不会失去校验）；彻底解决需要显式标记列（迁移）。
- `/v1alpha/` 等不在网关前缀清单里的路径，`/v1/v1/*` 式诊断 404 会被前端页面吞掉；`/backend-api/codex` 下 4 个及以上 `/v1` 不会被整段剥掉（与 #579 的「任意个」描述不符，新旧实现一致）。

## 部署

1. 从 Release 下载 `sub2api_2.3.155_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。
5. crypto 侧车最后换，盯 BSC / ETH / Polygon 游标持续前进，不前进立即回滚到 `v2.3.148-bsc6`。
