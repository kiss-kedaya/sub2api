# 2.3.144

## 修复：启用 Shamir 分片后充值扫描冻结、链上充值不到账

- **现象**：把钱包 vault 迁移到 v3 分片后，管理端「链上扫描」显示扫描速度 0 块/分、游标停在迁移时刻，BSC / Ethereum / Polygon 之后的所有链上充值都不再入账，热钱包异常流出监控也停摆。
- **根因**：扫描每轮都会走 security 阶段，原实现在该阶段用两个种子派生监控地址（`SecurityWatchEVMAddresses`）。v3 vault 的锁态是分片设计的正常稳态（内存里没有数据密钥），于是每轮都返回 `wallet signer is locked; a recovery shard is required`，整轮 scan pass 失败、游标不推进。
- **修复**：
  1. **监控地址改从已持久化的公开数据读取**（PR #526）：锁态下用无种子的事务读取经 MAC 认证的地址快照（`deposit_addresses` + `crypto_address_pool`）以及分片 set 时写入的热钱包地址（`crypto.signer.hot.addresses`）。监控钱包流出只需要地址，链上可见，不需要任何密钥 —— 因此锁态下流出监控照常运行，改库也无法伪造/隐藏地址。
  2. **扫描阶段容忍锁态**（PR #525）：若快照本身不可用，security 阶段跳过本轮流出监控而不是打回整轮，入账扫描继续推进；签名/归集仍然严格拒绝，无密钥不广播。
- **效果**：分片锁态下充值入账与异常流出监控都正常；签名、归集、导出仍然需要提交恢复分片解锁。

## 说明

- 无数据库迁移，无前端改动。
- 修复后无需解锁签名器，扫描游标会自动从冻结位置继续追平并补入账。
- 回滚：切回 2.3.143。
