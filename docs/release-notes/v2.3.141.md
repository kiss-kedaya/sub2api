# 2.3.141

## 资金安全：归集签名密钥改为浏览器持有的 Shamir 2-of-3 分片

- **服务器不再持有可分片的完整数据密钥**：钱包 vault 加密格式从 `sub2api-wallet:v2`（服务器安装密钥）升级为 `v3` —— 浏览器生成 32 字节数据密钥，用 Shamir 2-of-3 拆成三份：
  - **A**：提交给服务器（安装密钥封装）用于参与合成；
  - **B / C**：只在浏览器展示一次，由管理员自行离线保存，**任何情况下不发送给服务器**。
- 分片格式 `S2V1-…`（GF(256) 2-of-3，base32 + 版本/阈值/总数/索引/长度 + SHA-256 校验），前后端逐字节互通，携带固定测试向量。
- **解锁**：归集/导出/更换 Gas 助记词等签名操作需要提交任意一份恢复分片与服务器分片 A 合成数据密钥；合成结果仅在内存驻留并在操作结束时立即清零；连续 5 次错误分片锁定 15 分钟。
- **重新拆分**：持有任意两份旧分片可换新分片，旧分片立即失效。
- **锁态不影响收款**：热钱包地址、地址池、用户充值地址展示与入账扫描使用公开快照继续工作；每次解锁窗口会把地址池补足。
- **自动归集默认关闭**：开启需当场 TOTP + 后端下发的风险短语逐字确认 + 显式 `acknowledge_risk`，并把专用自动分片存到服务器（显式风险，建议只用于小额热钱包）。
- 前端在浏览器本地完成加密（WebCrypto，缺失时降级为纯 JS 实现，禁止弱随机；非 HTTPS 直接禁用）；分片只显示一次，支持复制/下载/打印二维码，要求回填验证后才能启用；分片、数据密钥不写入 localStorage/sessionStorage/IndexedDB/Cookie/URL。

- **未配置分片的部署行为不变**：vault 仍是 v2，签名流程与 2.3.140 一致。分片迁移需要管理员在后台主动执行。
- 无数据库迁移。
- 回滚：切回 2.3.140；已迁移为 v3 的部署需用分片 A 回退（文档见 `deploy/CRYPTO_SHARD_SETUP.md`）。
