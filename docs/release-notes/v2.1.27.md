# v2.1.27

内容审计记录改为展示「用户最后一轮输入」的解析结果。

## 问题

拦截记录的 `input_excerpt` 来自 `ExtractContentModerationFullText`，它有两个毛病：

1. **拼接了所有历史 user 轮次**，操作员看到的是从第一轮开始的一条长文本，而不是触发阻断的那一轮。
2. **与语义审计边界不一致**：真正送审用的是「最后一轮」（`extractContentModerationInput`），日志却展示全部轮次，二者对不上，无法据此复现判定。

## 改动

- 新增 `ExtractContentModerationLastUserTurn`，按协议解析出用户最后一轮输入：
  - `anthropic_messages` → `collectLastAnthropicUserMessage`（跳过尾部 system 消息）
  - `openai_chat` → `collectLastRoleMessage(role=user)`
  - `openai_responses` → `collectLastResponsesInput`
  - `gemini` → `collectLastGeminiContent`
  - 其他 → 三条路径依次尝试，取最先命中的
  - 纯图片轮次回退为图片 URL 列表，不留空
- 审计日志与语义审计现在共用同一「最后一轮」边界。
- 日志展示上限从 `maxModerationInputRunes`（12000，用于约束送审文本）换成独立的 `maxModerationLogExcerptRunes`（200000）。送审上限保持不变，只有展示字段放宽。
- 前端文案：`输入摘要详情` → `最后一轮输入`，`完整内容` → `用户最后一轮输入内容`（英文同步）。

## 测试

- `TestExtractContentModerationLastUserTurn_ParsesOnlyLatestTurn`：多轮对话只取最后一轮，且不含 system 与前几轮。
- `TestExtractContentModerationLastUserTurn_KeepsLongTurn`：超过送审上限的长输入不会被截断。
- `TestExtractContentModerationLastUserTurn_Responses`：Responses 形态同样只取最后一轮。

无新增数据库迁移。
