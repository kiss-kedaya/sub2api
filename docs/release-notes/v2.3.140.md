# 2.3.140

## 计费（本版重点）

- **流式异常结束不再漏计费**（#456）：上游 EOF、无终止帧结束、客户端断开、重试穷尽等场景，此前整笔调用被丢弃（不计费也不记录），异常结束时输入只按 95% 缓存读价估算（实际只收上游约 9.75%）。现在：
  - 上游已接受请求、无终止帧结束时保留计费结果，输入按请求体必计（0 输出也计），输出按真实产出；
  - 三入口（chat / responses / messages）重试前保留计费闭包，重试成功只计成功那次，穷尽/无号/客户端取消补记最后一次，结算幂等不会重复扣；
  - 估算缓存折扣口径与 new-api 对齐（默认 0%，可用 `BILLING_OPENAI_INCOMPLETE_INPUT_CACHE_READ_PERCENT=95` 回旧口径）。
- **非 Grok 通道的内置工具调用开始计费**（#491）：`web_search` / `web_search_preview` / `image_generation` 此前只在 Grok 通道计数，其余平台数出来也被丢弃。现在覆盖 responses / chat / messages / passthrough / Responses WebSocket / 协议转换链路与 Bedrock：
  - 补齐 `web_search_preview(_call)` 别名与大小写归一；
  - Anthropic 原生通道解析 `usage.server_tool_use.web_search_requests`，流式按累计最大值合并（不翻倍）；
  - 客户端自己声明的同名函数不会被误当内置工具重复收费；
  - 「图片 + 检索」同响应时两项叠加计费，不再整笔漏收；
  - 流在终帧前断掉，已完成的检索仍计费。

## 说明

- 无数据库迁移。
- 行为变化提示：异常结束的流式请求从此前的「几乎免费」变为按实际输入计费；非 Grok 平台的内置工具调用从此前「不计费」变为按价卡计费。若需暂缓，可用上一版二进制回滚。
- 回滚：切回 2.3.139；无数据不可逆变更。
