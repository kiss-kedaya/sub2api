# v2.3.175

本次是「用量接口继续减压 + 两处显示与隐私修正」版本：用户仪表盘、按 Key 的模型分布和窗口汇总不再每隔一段时间就把整个窗口（含不会再变的历史）重扫一遍，数据库繁忙时仪表盘也不再直接报 500；错误信息里的官方帮助 / 申诉链接不再被打码；用量记录的「费用明细」按标准价显示，不再把上游的档位价当成用户价。

## 亮点

- **用户仪表盘汇总拆成「已关闭的天 + 今天」两段，超预算不再 500**（#675）：2.3.174 切流后的第一分钟里，`GET /api/v1/usage/dashboard/stats` 约 28% 的请求返回 500（`canceling statement due to user request`，即自己的 15 秒加载预算在数据库繁忙时先到）；同一时段的慢语句日志里，按平台拆分的那条语句 10 分钟出现 10 次、合计 44 秒、最长 8.8 秒——每次缓存过期都把一个用户整个窗口（保留期内最多 15 天）重新聚合一遍。
  - **已关闭的天**（生命周期小时汇总 + 窗口内按平台拆分）缓存 26 小时；**今天**（今天的小时汇总、当前小时、今天的按平台拆分、RPM / TPM）按缓存默认时长刷新，每次只重读今天的行；
  - 总量 = 两段相加，今日量 = 今天段，按平台按名字相加，平均耗时由「耗时总和 / 次数」重建（不是平均数的平均）；切点是应用时区的本地午夜，不是 now-24h；每个本地日的第一个小时仍整段回答（小时汇总在零点后的最后一小时还没定稿，提前关死会错一整天）；没有缓存、窗口里没有已关闭的天时整段回答，和以前一样；
  - 加载预算耗尽 / 语句超时 / 语句被取消时改回 `429` + `Retry-After`（与并发闸同一套，不再记成 `[ERROR]`）。
  - 验证：真实 PostgreSQL 差分测试（拆开的答案必须逐字段等于「整个窗口一次读完」）、handler 端到端、变异检查。
- **按 Key 的「按模型分布」和「窗口汇总」同样拆段**（#677）：`/v1/usage` 的 `model_stats`、`/v1/sub2api/usage` 的区间汇总、用量页 / 管理端按 Key 过滤的模型分布。2.3.174 在线时的慢语句日志（≥2.5 秒，10.4 分钟）里，按 Key 的模型分布是最大的一类：34 条、239 秒，占全部慢语句数据库时间的 51%。
  - 窗口分三段：**头**（起点到第一个本地午夜，不足一天，随起点平移，缓存 15 分钟；窗口从午夜开始时没有头）、**已关闭的整天**（缓存 26 小时，最重的就是这一段）、**今天**（缓存默认时长）；
  - 模型分布按模型名求和、排序与原查询一致（同分按模型名）；窗口汇总的平均耗时由总耗时和请求数重建；
  - 不动：账号维度的模型合计（限流 / 配额准入用）仍然实时；rollup 读路径、整窗口读时的缓存键与 TTL 与改前逐字节相同。
  - 验证：真实 PostgreSQL 差分测试（1734 个窗口 × 三个模型来源 + 四种过滤 + 汇总，拆与不拆逐字段相等）、变异检查。
- **错误信息脱敏不再吞掉官方公开链接**（#676）：中转账号的 Anthropic 组织被停用时，上游返回里的申诉页 `https://console.anthropic.com/appeal` 在客户端响应、后台诊断页「客户端响应」和入库的「上游消息」里都被打码成 `[redacted]`，客户端无法申诉。现在只放行 **https** 且主机精确等于下列官方文档 / 控制台 / 支持 / 状态页之一、无端口 / 用户信息 / 查询串 / 片段、路径只含安全字符的链接：`console.anthropic.com`、`docs.anthropic.com`、`support.anthropic.com`、`status.anthropic.com`、`www.anthropic.com`、`anthropic.com`、`platform.openai.com`、`help.openai.com`、`status.openai.com`、`community.openai.com`、`www.openai.com`、`openai.com`、`ai.google.dev`、`cloud.google.com`、`console.cloud.google.com`、`support.google.com`。其余（中转站地址、上游 API 域名、带参数的链接、`base_url=…` 这类赋值）照旧脱敏；输入里已含占位符字符时整体退回「所有链接都脱敏」，占位符无法被伪造。
- **用量记录的「费用明细」按标准价显示**（#678）：Fast / UltraFast 行后端存的分项金额和 `total_cost` 一样是上游按档位实际收的价（UltraFast 官方是标准价的 6 倍），弹窗上半块（输入 / 输出费用、输入 / 输出单价）因此显示 6 倍价，和下面的档位倍率 1×、用户扣费对不上，看起来像被按 6 倍收费。**扣费本身没有问题**（用户实付 = 标准价 × 档位倍率 × 分组倍率），这次只改显示：有档位的行按「标准价 ÷ total_cost」等比缩放，标题变成「费用明细（标准价）」，输入费用 + 输出费用 = 原始（标准价），原始（标准价）× 综合倍率 = 用户扣费；管理端的「上游成本」不动。老数据、带按次加价或图片分项的行保持原样。

## 变更清单

### 优化

- 用户仪表盘汇总拆成「已关闭的天（缓存 26 小时）+ 今天」两段（#675）
- 按 Key 的模型分布与窗口汇总拆成「头 + 已关闭的整天 + 今天」（#677）

### 修复

- 用户仪表盘加载预算耗尽 / 语句被取消时返回 500，改为 429 + `Retry-After`（#675）
- 错误信息脱敏把官方公开的帮助 / 申诉链接打码（#676）
- 用量记录的费用明细把上游档位价当成用户价显示（#678，只改显示）

## 升级与兼容说明

- **数据库迁移**：无。可直接从 2.3.174 蓝绿替换，旧二进制可回退。
- **行为变化（有意的）**：
  - 用户仪表盘、按 Key 的模型分布与窗口汇总里，已关闭的天最多滞后到次日本地午夜（按 Key 的两类最多 26 小时）：迟到的用量行、手工改写的历史用量要到缓存换键之后才反映到这些**展示**里；不影响余额、计费、限流和任何准入判断。
  - 每个本地午夜之后的第一轮，所有活跃 Key 的已关闭段同时未命中（缓存键换了）：每个 Key 一次，成本约等于之前 15 分钟一次的整窗口扫描，全天只一次；并发仍受并发闸与 28 秒预算限制。
  - 用户仪表盘在数据库繁忙时返回 `429` 而不是 `500`；前端仪表盘页目前对任何错误显示同一个错误态（用量页已能识别并重试）。
  - 客户端错误里的官方帮助 / 申诉链接现在会原样保留（只限上面 16 个主机）；已入库的历史记录不会回填，仍显示 `[redacted]`。
  - 用量记录「费用明细」对 Fast / UltraFast 行显示标准价口径（标题带「标准价」）。
- **已知限制**：
  - 缓存（Redis）不可用时，每次调用最多 3 条语句而不是 1 条（读的行总数不变）。
  - 按 Key 的「今天」段按缓存默认时长重读：持续每分钟轮询的重 Key 总读量降幅小于每 10 分钟轮询的 Key。
- **回退**：回退到 2.3.174 即恢复整窗口单次查询；新键与旧键互不读取，蓝绿期间共用 Redis 不会串。
- **页面刷新**：本版有前端改动（#678），发版后请刷新页面。
- **crypto 侧车**：本版没有改动扫链 / 归集代码，侧车保持 2.3.155 即可，不必更换。
