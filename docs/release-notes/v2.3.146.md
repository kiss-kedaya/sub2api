# 2.3.146

## 新增：充值/兑换整改页支持「我已知晓风险，继续充值」

- **背景**：泄漏事件后，未更换 API Key 且未设置 IP 白名单的用户会被拦在充值/兑换之外。部分用户明确不愿意轮换 Key 也不愿意配白名单。
- **新增**：整改提示卡片上增加次级按钮「我已知晓风险，继续充值」，点击后弹出风险确认（说明：Key 未轮换/未加白名单时，一旦泄漏他人可直接盗刷余额），确认后：
  - 记录一条风险确认（`key_rotation_risk_acks`，含有效期、客户端 IP/UA、当时的 cutoff 快照）；
  - 有效期内放行充值/兑换，页面显示「风险确认有效期至 HH:mm」；
  - 到期或被新切换点（cutoff）失效后，重新拦截；
  - 全程写审计（确认动作 + 放行动作），可追溯。
- **后台可配**：`security.key_rotation_risk_ack_enabled`（默认开）、`security.key_rotation_risk_ack_hours`（默认 24，范围 1–720）。
- 模型调用、余额查看、Key 管理不受此拦截影响（与原有门禁一致）。

## 修复：用户 Bark 推送配置不再强制 2FA

- **问题**：个人资料里每改一次 Bark 推送配置都要求先绑定并输入 2FA，普通用户几乎无法使用。
- **原因**：Bark 设备 Key 只决定「该用户自己的通知推到哪」，不涉及余额、上游凭证或管理能力，却走了 fresh-TOTP 校验。
- **修复**：去掉该接口的强制 2FA，改为分层防护：
  - Key 加密存储、接口永不回显；
  - 变更前先向**原设备**发通知，原通道发不出就拒绝修改（防止被劫持后静默改推送地址）；
  - 仍强制 HTTPS 提交。
