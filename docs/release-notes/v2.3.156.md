# v2.3.156

本次为安全加固版本：管理员触发的出站请求（模型同步、账号测试、CRS 同步、DeepSeek 自填搜索地址）只允许访问公网主机，连接建立时再校验一次；智能路由 Key 的入口协议守卫按全部候选分组判定；Responses 桥的入站 query 改为白名单；新增默认关闭的备份「关键表快照」模式。无数据库迁移，扫链代码相对 2.3.155 无改动。

## 亮点

- **管理员触发的出站请求只访问公网**：账号「同步模型列表」（预览、已保存账号的同步、白名单自动同步）发出的请求默认只允许访问公网主机，并且不再跟随 3xx 重定向；直连（未配代理）时，连接建立那一刻会对已解析出的 IP 再校验一次，校验与建连之间 DNS 改指内网也拦得住。账号测试、CRS 同步、DeepSeek 自填搜索地址三处的「是否公网」判定合并成同一个函数：DNS 解析失败 / 解析为空一律按拒绝处理（此前放行），私网网段清单扩到完整的特殊用途地址段。管理员显式放行私网时（`allowlist` 开启且 `allow_private_hosts=true`），模型同步保持原行为。
- **智能路由 Key 的入口协议守卫**：主分组关闭「跨协议转换」、后面的 Anthropic 分组开启转换时，`/v1/responses`、`/v1/chat/completions` 不再在入口被 400 `PROTOCOL_MISMATCH` 拦下，而是按顺序正常选号；只有全部候选分组都关闭转换才在入口拒绝。选中分组在转发阶段仍会再校验，错误码与响应体不变。
- **Responses 桥入站 query 白名单**：`POST /v1/responses` 的 query 不再原样并入上游 URL，只转发 `beta`；另有凭证类名称拒绝清单（即使白名单被误放宽也不放行）、16 个键 / 64 字节值的上限；上游 URL 里已有的键不会被覆盖。
- **备份「关键表快照」模式（默认关闭）**：可对指定的大表只导出结构不导出数据，归档在离开本机前用 age 公钥加密，并有体积上限；不配置任何新项时备份行为与上一版完全一致。

## 变更清单

### 新增

- 内置备份新增可选的「关键表快照」模式：排除大表数据 + age 加密 + 体积上限（#583）

### 修复

- 管理员触发的出站请求只访问公网：模型同步挂「仅公网 + 禁重定向」并补上拨号期校验；账号测试 / CRS / DeepSeek 自填地址的公网判定统一、解析失败即拒绝（#591）
- 智能路由 Key 的入口协议守卫按全部候选分组判定；Responses 桥入站 query 改为白名单（#592）
- 扫链包「链校验缓存」的单测互相污染导致主干 CI 偶发失败，改为测试内隔离（仅测试代码，生产逻辑不变）（#595）

## 升级与兼容说明

- **数据库迁移**：无。
- **模型同步不再跟随 3xx**：http→https、补斜杠、换域名跳转的中转站会报 `Upstream model list request failed with HTTP 30x`，把 `base_url` 改成最终地址即可。
- **DNS 解析失败改为拒绝**：此前放行（随后的请求多半也失败）。账号测试 / 模型同步返回 400（固定文案，不带主机与解析细节）；上游计费探测遇到 DNS 抖动会记一轮 `invalid_base_url`、下一轮恢复；配了自填搜索地址的 DeepSeek 分组在 DNS 故障时直接返回 502。
- **私网网段清单扩大**：账号测试 / CRS / DeepSeek 自填地址的判定新增 `198.18.0.0/15`（常见 fake-ip）、`240.0.0.0/4`、组播、`192.0.0.0/24`、6to4，以及非 `2000::/3` 的 IPv6（如 NAT64）。经 fake-ip 或 DNS64 / NAT64 解析的上游主机会被拒绝；常规公网域名不受影响。
- **走代理的账号**：拨号目标是代理本身，拨号期校验不适用；请求前的校验仍在本机解析主机名，所以目标主机需要能在本机解析。
- **Responses 的 query**：除 `beta` 外的参数不再到达上游。如有客户端依赖自定义 query 到达某个中转，需要把对应键加进白名单（`forwardedInboundQueryKeys`）。Anthropic 非 Vertex 的上游 URL 本来就带 `beta=true`，这类请求无变化。
- **备份**：默认关闭，不设置任何 `BACKUP_*` 时行为不变。配置了 `exclude_table_data`（关键表模式）却没有 age 公钥时，配置加载直接失败（设计如此，不会退化成明文）。蓝绿期间没配置 `BACKUP_*` 的实例（含回滚实例）仍按旧行为跑整库备份：要启用就先停掉旧实例 / 回滚实例再打开定时，且每台实例的 `BACKUP_*` 必须一致。启用方式见 `deploy/config.example.yaml`。
- **新增直接依赖**：`filippo.io/age v1.2.1`（仅备份加密使用，默认不启用）。
- **crypto 侧车**：本版没有改动扫链代码，侧车可以保持在 2.3.155，不必随本版更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 智能路由候选组里有一个开启转换、但因平台 / 模型不匹配实际选不上时，请求会走到选号并得到 503，而不是入口的 400（「不预先跳过」口径下的保守取舍）。
- 备份：前端对「关键表 / 加密」记录仍显示「恢复」按钮，点击得到 `BACKUP_RESTORE_UNSUPPORTED`（在线还原对这类记录一律拒绝，手动还原步骤见 #583）；归档的 `sha256` 只防篡改、不是签名；失败的定时备份不会触发过期清理，建议在对象存储桶上另配生命周期规则兜底。

## 部署

1. 从 Release 下载 `sub2api_2.3.156_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。
