# v2.2.6

网关的流式语义与上游官方对齐：不再提前提交 200、已提交 200 后不再换号、
错误状态码按官方透传，并停止无条件把同步请求改成流式。

## 1. 不再提前提交 200（核心）

`/v1/messages` 的结构化流式入口在**请求上游之前**就启动 SSE 心跳；一旦超过
心跳间隔就 `WriteHeader(200)` 并写 `: keepalive`。

上游经常要十几秒才返回，而它真实给出的是 `400 prompt is too long` 这类错误。
此时状态码已经被固化，客户端看到的是「200 + 若干 ping + 流正常结束」，
既拿不到错误，也判定不出终止事件。

修复：

- 新增 `GateOpenAIStreamSSEKeepaliveUntilUpstream`：上游响应头到达前心跳静默。
- 新增 `ArmOpenAIStreamSSEKeepalive`：上游确认 `200 + text/event-stream` 后才解锁。
- 等槽位心跳 `WriteOpenAIStreamSSEHeartbeat` 同样受该门控约束。
- `compact` 路径保持「先 200、流内 `response.failed`」的既定语义。

## 2. 已提交 200 后禁止换号

新增 `IsOpenAIStreamSSEKeepaliveArmed`。下游 SSE 响应头一旦提交，状态码无法
回退，换号也不能撤销，因此禁止 failover。

补齐全部门禁位置：`openAIForwardMayFailover`、Messages 主循环与 Gemini 子循环、
chat-completions、responses、OpenAI 原生 chat、`/v1/messages` 走 OpenAI 上游。

## 3. 状态码按官方透传

`anthropicStreamErrorSemantics` 增加映射：

| 上游 error.type | 之前 | 现在 |
|---|---|---|
| `invalid_request_error` | 502 | **400** |
| `not_found_error` | 502 | **404** |
| `authentication_error` | 502 | **401** |
| `permission_error` | 502 | **403** |
| `overloaded_error` | 529 | 529 |
| `rate_limit_error` | 429 | 429 |

另外：`event: error` 后若没有跟随 `data:` 行就收尾，会补写该帧，避免整帧丢失。

## 4. 不再无条件强制上游流式

`ForwardAsAnthropic` 改为跟随客户端 `stream` 偏好。只有 Codex OAuth transform
这种确实只支持流式的账号才保持强制。

## 5. budget_tokens 自动改写默认关闭

新增配置 `GATEWAY_THINKING_BUDGET_RECTIFY_ENABLED`（默认 `false`）。

该链路在收到 budget 约束错误后，会把 `thinking.type` 改成 `enabled`、
`budget_tokens` 改成 32000、`max_tokens` 改成 64000 再重发——属于替客户端
放大预算，与官方不一致。需要时再显式打开。
