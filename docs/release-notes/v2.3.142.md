# 2.3.142

## 修复：6 位动态验证码输入框在 iOS 上点了就收起键盘

- **现象**：iOS（Safari / 手机端）在「验证恢复分片」「安全校验」「分片生成向导」等弹窗里点 6 位动态验证码，键盘弹出后立刻收起，反复跳动，数字根本输不进去。
- **根因**：共享验证码组件用一个 `opacity: 0` 的真实 `input` 覆盖在 6 个展示格上，并在 `pointerdown` 里 `preventDefault()`：
  - Mobile Safari 不把 `opacity: 0` 的元素当作真实文本字段，聚焦后立即失焦；
  - `preventDefault` 掉 pointer/touch 默认行为等于取消用户手势，键盘被立即 dismiss；
  - 弹窗挂载时的 `autofocus` 与 modal 自己的焦点管理抢焦点，加剧「弹一下就收」。
- **修复**：
  - 输入层改为**元素可见、文字与光标透明**，保持它是正常文本框；
  - `pointerdown` 不再 `preventDefault`，只在对齐光标时 `setSelectionRange`；
  - 增加 `enterkeyhint="done"`；
  - crypto 三个弹窗显式 `:autofocus="false"`，打开时不再抢键盘。
- 桌面端行为不变：点格子仍按位置对齐光标，粘贴/自动填充仍整段填入并自动提交。

## 说明

- 纯前端交互修复，无数据库迁移，无后端行为变化。
- 回归测试：`TotpCodeInput` / `ShardUnlockDialog` / `SignerShardSetupWizard` / `CryptoSecurityDialog` 四个 spec 共 38 条通过，含新增 iOS 用例（断言输入层不是 `opacity-0`、`pointerdown` 未被 `preventDefault`）。
- 回滚：切回 2.3.141。
