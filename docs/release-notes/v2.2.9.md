# v2.2.9

三件与"模型列表 / 模型白名单"相关的问题。

## 1. 单分组 `/v1/models` 返回空数组

`availableModelsForAPIKey` 里 `injectDefaults := len(groupIDs) > 1`：只有绑定
多个分组的智能路由 key 才会注入平台默认模型。单分组 key 在两种情况下拿到
空数组：

- 账号侧没配 `model_mapping`，`GetAvailableModels` 解析不出任何模型；
- 账号侧配了封闭 `model_mapping`，但当前平台没有任何可用账号。

客户端 `/v1/models` 因此什么都看不到。

修复：`injectDefaults` 恒为 `true`。注入只在"完全没解析出模型"时生效，
不会覆盖账号真实映射出来的结果。

## 2. Claude 默认模型列表过时

按生产近 7 天 `usage_logs` 的真实调用量补齐 `claude.DefaultModels`：

新增 `claude-sonnet-5-5`、`claude-haiku-5-5`、`claude-sonnet-5`、
`claude-opus-4-8`、`claude-opus-4-7`、`claude-opus-4-6`、`claude-sonnet-4-6`、
`claude-opus-5`、`claude-opus-4-5`、`claude-sonnet-4-5`、`claude-haiku-4-5`，
删除重复条目。现共 17 条，无重复。

## 3. 模型白名单输入框不支持批量粘贴

粘贴多行文本时，整段被当成一个模型名（含换行），校验失败。

修复：`addCustomModelAllowlistItem` 按换行 / 逗号 / 分号 / 制表符 / 空格
拆分，逐条追加并跳过重复项。单条输入行为不变。

## 未改动（有意）

- 国产供应商（deepseek / zhipu / kimi / minimax）**继续沿用 Claude 默认列表**。
  既有测试 `TestDefaultModelIDsForPlatform_CNProvidersKeepClaudeDefaults`
  明确断言这条：Claude Code 客户端请求的就是 Claude 模型名，靠账号级
  `model_mapping` 转换到上游厂商。给这些平台单独塞国产模型名会破坏该链路。
- 账号级 `model_mapping` 非空即视为**封闭白名单**，不在其中的模型返回
  `model_not_found`。要放行需在账号上补映射，或使用不配 mapping 的账号。
