# 2.3.105

## 计费

- **上游明确报错的请求不再扣费（OpenAI 兼容网关、DeepSeek 联网搜索、Gemini）**。规则和 2.3.104 相同：上游自己返回了错误——HTTP 4xx / 5xx 错误响应、流里明确的错误事件、
  HTTP 200 的错误信封——这条请求就不向用户收费，即使上游在报错之前已经报过用量、已经出过一部分字。断流（上游没有明确报错、连接中断或缺结束帧）、
  用户自己断开、网关空闲超时：收费方式不变。
  - **`/v1/responses`、`/v1/chat/completions`、`/v1/messages`**（OpenAI、Grok、Kimi、DeepSeek 等走 OpenAI 兼容网关的分组）：流里收到上游的 `error` /
    `response.failed` 不扣费。以前只有「还没出字，并且是少数几种报错文案」才不扣。输出到上限（`response.incomplete`）不是报错，照常收费。
  - Chat Completions 回退、原生 Anthropic 兼容、原样转发的 Chat Completions：同样处理。非流式响应本身是 HTTP 200 错误信封的，
    以前会被转成一个空的成功回答并照常扣费；现在用户收到的是错误，不扣费。
  - **DeepSeek 联网搜索**（一次请求里多轮模型调用 + 搜索）：任意一轮被上游明确报错结束，或被网关的等待上限结束，整条请求不扣费——模型费和搜索费都是 0。
    以前按前几轮已计量的用量和搜索次数收费。搜索 / 抓取工具失败、但模型最后正常答完的，照常收费。
  - **Gemini**：原生接口和 `/v1/messages` 入口，上游返回明确错误的不扣费，用户收到的是错误，而不是一个空的结束帧。内容安全拦截的收费方式不变。
  - 上游先报了一次错、后面又正常答完，并且回答已经交到用户手里的，照常收费。
  - 网关自己判定的失败（例如 Excel 加载项的本地校验没通过）不算上游报错，收费方式不变。
  - 带着正常回答的响应，即使旁边夹着一个 error 字段（中转加的备注、空对象），照常收费。
- 这次没有改的：WebSocket、Bedrock、Antigravity、图片接口，以及搜索 / 嵌入 / 语音接口的 HTTP 200 错误信封。
  几种少见的上游返回形态（流里不带类型的错误帧、报错之后又跟一个没有任何回答的成功结束帧、Gemini 的具名 error 事件等）这一版还按原来的方式收费，下一版处理。
  审核 / 风控类拒绝（Grok 违规拒绝的固定收费、cyber policy、Gemini 内容安全拦截）收费方式不变。

## 修复

- Gemini 原生接口桥接到 Responses 上游时，如果上游先发了一个错误前奏、随后又正常回答，回答内容会被丢掉，用户只收到一个空的结束帧。现在回答正常转发。

## 升级注意

- 无数据库迁移，无前端改动。
- 用量记录里这类请求可能仍有一行（保留了 token 数），金额为 0。
