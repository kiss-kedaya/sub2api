- 安全：修复出站地址的解析后 IP 校验被错误地与 URL 白名单开关耦合的问题。此前的写法是「白名单开着才校验解析后的 IP」，于是关掉白名单会被**静默解释成连 DNS Rebinding 防护也一起关掉**；在「白名单关闭 + 不允许私网」这种配置下完全没有校验，可以直连私网与环回地址。现在只由「是否允许私网地址」这一个开关决定，语义明确。
- 安全：把依赖漏洞的清理变成 CI 能拦住的事。`govulncheck` 原先只在**代码真的调用到**漏洞时失败，「依赖里有漏洞但没调用到」这类发现既不失败也不打印，于是长期无人处理（实测积了 11 条，其中图片解码库一个模块占 5 条）。现在这些发现会逐条以警告形式出现在流水线里，**只要存在有修复版的就判定失败**，避免继续堆积；同时升级了 4 个受影响模块。另外给漏洞扫描步骤补上了管道退出码保护——否则末尾的 `tee` 会盖掉真实退出码，可达漏洞反而不会让构建失败。
- 安全：`xlsx` 的高危豁免不再靠一句注释维持。该库仅用于管理端的用量导出，且**只写不读**（两条漏洞都在解析路径上，因此不可达）。新增测试把「只写不读」变成强制前提：一旦有人引入解析接口或改成同步导入，CI 直接失败。同时清理了 3 条已经不对应任何漏洞的陈旧豁免——其中一条是严重级别、已过期两个多月却没让流水线变红，因为该漏洞已不在扫描结果里，这类条目只会造成「已被跟踪」的错觉。
- 性能：`/v1` 请求不再被整个复制两份。请求模型提取原先调用两次 JSON 解析入口，而该入口会把整份请求体复制成字符串；现已合并为单次遍历并改为零拷贝，分配量不再随请求体大小增长（1 MB 请求体从约 2.1 MB 降到 112 字节）。候选值会拷贝出来，避免与调用方的缓冲区共享内存。
- 性能：流式（SSE）每帧的解析开销大幅下降。原先每个事件都要用两次正则剥 `data:` 前缀，并逐条扫描财务错误信封；现在前缀解析改为字符串操作，财务扫描增加一个**可证明安全**的廉价前置判断——它五个分支的触发词只有 error 与 failed 两个，普通帧两者都不含，因此可以直接返回。实测普通帧从 329.5 ns / 96 字节降到 90.9 ns / **零分配**。
- 性能：设置缓存不再加载邮件投递台账。设置表里 98% 的行是「每封邮件一条、每个收件人一条」的投递记录，它们全部按精确键读取、从不参与「读出全部设置」，却因为全量读取逻辑而每次都被装进内存并整份复制。排除后单次加载从 17,265 行降到 303 行。
- 性能：Grok 请求体改写去掉一次重复的整份 JSON 校验（入口已校验过，内部又校验一遍）。完整的 JSON 校验是一次无复用的全量扫描，在生产采样中占相当比例的 CPU。
- 质量评审：降智评审补严——鸟悬空飘在车上方（身体与车架之间有明显空隙）、腿折叠在车架里不朝踏板，判降智（此前过松被放过）；确认误判为通过的记录已改回降智。
