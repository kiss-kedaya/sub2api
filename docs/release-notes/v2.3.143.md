# 2.3.143

## 修复：IP 白名单弹窗的「常用 IP」一直空着

- **现象**：用户打开 API 密钥的 IP 白名单弹窗，点「常用 IP」，长期显示「最近没有可用的 IP 记录」，但账号其实每天都在用，后台审计日志里有上万条带客户端 IP 的记录。
- **根因**：最近 IP 读取有两个数据源（用量连接明细 `request_connection_traces`、审计日志 `audit_logs`），两者共用同一个 2 秒超时：
  - 用量明细那条 SQL 是「先按时间排 2 万行再聚合」，生产实测 **4.5 秒**，必然吃满整个预算；
  - 随后的审计日志兜底查询拿到的是**已经过期的 context**，立即失败；
  - 服务层把失败降级成空列表，前端就显示没有记录。
- **修复**：
  - 用量明细查询改为直接 `GROUP BY` 聚合（不再对 2 万行排序），30 天窗口实测 **300ms**（7 天窗口 30ms）；
  - 两个数据源各自独立预算（各 900ms），并改用 `context.WithoutCancel` 派生，慢查询不会再吞掉另一条路径的预算，兜底一定跑得起来；
  - 保留原有过滤：只返回可写入白名单的纯 IP（`host:port`、主机名、空值丢弃）。
- **效果**：打开弹窗能列出最近 30 天访问过的最多 5 个地址（按出现次数倒序），点一下即可填入白名单。

## 说明

- 无数据库迁移，无前端改动，接口响应结构不变。
- 回归测试：新增「用量明细超时但审计日志兜底仍返回数据」用例；`go build ./...` 与 repository/service/handler 相关测试全绿。
- 回滚：切回 2.3.142。
