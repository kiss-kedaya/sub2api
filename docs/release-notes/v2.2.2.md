# v2.2.2

修掉第三方 Responses 上游对 `web_search_preview` 的工具类型拒绝，并接入 DeepSeek 官方账号。

## 1. web_search_preview 兼容

OpenAI 已把 `web_search_preview` 标为旧名（官方内部折算成 `web_search`），但多数第三方 Responses 兼容上游只认新名，收到旧名直接 400：

```
Unsupported tool type: web_search_preview
```

43 组（GPT 不降智，0.14x）7 天累计 1,052 次，全部是这一条。直连上游 `routex.best` 实测：`web_search` → 200，`web_search_preview` → 400，确认此前网关原样透传。

修复：出站前把 `tools[].type` 与 `tool_choice.type` 上的 `web_search_preview`（含带日期后缀的变体）折算成 `web_search`，其余字段原样保留。

- 没有该字面量时只做一次 `bytes.Contains` 就返回，不解析 JSON。
- 覆盖 HTTP `/v1/responses` 与 Responses WebSocket 两条出站路径。

## 2. DeepSeek 官方账号

新增一条 DeepSeek 官方账号，`api_protocol=adaptive`，接入 36 组（DeepSeek）：

| 协议 | 地址 | 实测 |
|---|---|---|
| Chat Completions | `https://api.deepseek.com` | `deepseek-v4-pro` / `deepseek-flash` 均 200 |
| Anthropic Messages | `https://api.deepseek.com/anthropic` | 两个模型均 200 |
| Responses | `https://api.deepseek.com` | 200 |

账号按 adaptive 配置三套 `api_base_urls`，模型映射覆盖 `deepseek-flash`、`deepseek-v4-pro`。启用 `upstream_billing_probe`。
