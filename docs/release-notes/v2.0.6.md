## 修复：/v1/messages 命中上游缓存

- 问题：adaptive 协议的国产账号走 `/v1/messages` 时被零转换直通到上游 `/v1/messages` 端点，实测该端点不返回 prompt 缓存（同一 key 缓存恒为 0），用户缓存命中率只有 8~12%。
- 实测对照：同一上游、同一模型，`/v1/responses` 与 `/v1/chat/completions` 都有缓存。改后 DeepSeek 缓存命中从 8~12% 升到 84~86%。
- 改动：adaptive 账号不再走原生 Anthropic 直通，改按账号能力选端点——有原生 Responses 的平台（deepseek/kimi/minimax）走 Responses，其余回退 Chat Completions。
- 显式 `api_protocol=anthropic` 的账号保留原直通路径，行为不变。
- 去掉分组的 `allow_messages_dispatch` 闸门。

## 配置变更

- 上游账号的 `base_url` 与 `api_base_urls` 统一补上 `/v1` 后缀，否则 Responses/Chat 端点会拼出 404 路径。
