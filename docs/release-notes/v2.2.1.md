# v2.2.1

修掉 Claude 5.x 全系列的 `requires adaptive thinking` 400，覆盖所有出站路径。

## 问题

过去 7 天 `ops_error_logs` 里这条 400 有 10,038 次，集中在三个入口：

| 入站 | 上游 | 次数 |
|---|---|---|
| `/v1/chat/completions` | `/v1/messages` | 7,715 |
| `/v1/messages` | `/v1/messages` | 1,956 |
| `/v1/responses` | `/v1/messages` | 85 |

上游实测（opus-5-5 / sonnet-5-5 直连）：

| 请求 | opus-5-5 | sonnet-5-5 |
|---|---|---|
| 省略 `thinking` | 200 | 200 |
| `adaptive` | 200 | 200 |
| `enabled`（带不带 `budget_tokens`） | 400 | 400 |
| `disabled` | 400 | 400 |
| `between_tools` | 400 | 200 |

## 根因

1. 2.1.x 的 thinking 门只挂在原生 `/v1/messages` 和 apikey passthrough 两条路径上。CC 与 Responses 入站走 `apicompat` 转换链，会把 `reasoning.effort` 合成成 `thinking.type=enabled + budget_tokens`，而这两条 forwarder 从来没调用过该门。
2. 门本身只处理 `enabled`。客户端显式关思考发 `disabled`，上游同样 400，必须整段删除（改 adaptive 会把用户关掉的思考又打开）。
3. `sonnet-5-5` 接受 `between_tools`，`opus-5-5` 不接受，不能一刀切。
4. `count_tokens` 共用同一套 thinking 校验，同样漏接。

## 修复

- thinking 门扩展为三态：`enabled` → `adaptive`（删 `budget_tokens`）；`disabled` → 删除 `thinking` 并清理依赖它的 `context_management` 编辑项；`between_tools` 仅在 sonnet 保留、opus 转 `adaptive`。
- 接入所有出站点：`ForwardAsChatCompletions`、`ForwardAsResponses`、两条 OpenAI 网关原生 Anthropic 转发、两个 `count_tokens` 构造器、国产原生 Anthropic 直通。
- 性能：非 Claude 5.x 模型名只做一次字符串/正则判断就返回，不解析 JSON；只有 `thinking` 是对象时才走 `sjson`。
- 单测补三态分支、`context_management` 清理、sonnet/opus 的 `between_tools` 差异，以及 CC 入站的端到端 wire body 断言。

无数据库迁移。无配置变更。
