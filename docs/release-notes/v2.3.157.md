# v2.3.157

本次为错误信息脱敏与管理端筛选面板体验版本。无数据库迁移，扫链与计费代码无改动。

## 亮点

- **「选不到账号」的错误不再向调用方暴露调度内部信息**：`/v1/messages`、`/v1/responses`、`/v1/chat/completions` 与 Gemini v1beta 的 503 / 429 只返回固定文案（保留 `No available accounts` 前缀）；完整诊断改记服务端结构化日志，按 request id 检索。404 的「当前可用模型」只列该分组对外可见的模型（按分组模型白名单过滤，和 `/v1/models` 同一规则），不再带出被白名单隐藏的别名。
- **选号失败的分类不再从错误文本里解析**：选号层随错误携带结构化计数，handler 用它判定 404 / 403 / 429 / 503。请求里带括号、`pool=`、`model_not_supported=` 之类字样的模型名不能再改变判决；智能路由有候选组被跳过时，本该是 404 / 429 的失败也不再退化成可重试的 503。
- **管理端「用量明细 / 错误请求 / 用户排行」的筛选面板重做**：高级筛选和常用项同一套 4 列网格，去掉分组小标题和分隔线，面板高度约减半；未设置的筛选统一显示淡色的「全部…」，有值才是亮色（原来一律显示成「请选择」，读起来像必填）；用户 / API 密钥 / 账户搜索改成边输入边搜，点外面或按 Esc 收起列表，搜不到时给「无匹配选项」，高级区收起时不再把列表裁成一行半；被截断的名字和自定义时间范围悬停可读全文；「高级筛选」有生效条件时按钮不再只剩一个数字。展开只做 160ms 淡入，按钮按下缩到 0.97，减少动态偏好下去掉位移。

## 变更清单

### 修复

- 选不到账号的错误响应脱敏；404 模型列表按分组白名单过滤；选号失败分类改读结构化计数，路由摘要不再把分类挤成 503（#593）
- 用量 / 错误请求筛选面板：网格化、「全部」显示、边输边搜、下拉收起与不被裁切、无匹配提示、悬停读全文、动效与减少动态偏好（#597）

## 升级与兼容说明

- **数据库迁移**：无。
- **客户端文案**：503 / 429 的 `message` 变成固定短句，不再含分组、池内计数、跨协议开关等内部信息；`code`、HTTP 状态码、响应体结构、`Retry-After` 不变，依赖 `No available accounts` 前缀的 ops 过滤与渠道监控分类仍能识别。
- **排障方式**：依赖旧 503 文案里诊断细节的人工排障，改看服务端日志里的 `*.select_account_no_available`（带 `protocol_diagnostics` 字段，与请求同一 request id）。ops 错误记录表与用户侧「错误请求」页展示的是客户端同款文案，不再带诊断计数；如需在 ops 表里保留诊断，需要单独的管理员专用字段（要改表，本版没做）。
- **404 模型列表**：只列请求所属分组对外可见的模型；分组信息没加载或对不上时不展示列表。
- **筛选面板**：只改前端展示与交互；传给页面的筛选值（`null` / `undefined` 的存法）不变。移除三条不再使用的文案键，请求 ID 与上游模型审计的说明改短。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 自定义时间范围在 1440 宽以下的笔记本上会被截断结束时间（悬停可读全文）；要彻底解决需要把日期列做宽，代价是常用行与下面几行的列边不再对齐。
- 分组 / 模型下拉没有虚拟化：选项上千时打开需要约 0.8 秒；常见部署的分组数远低于这个量。
- 429 的判定口径沿用「池内有账号处于模型级冷却即判 429」，该诊断不覆盖配额 / 窗口费用 / RPM / 渠道限制等其它不可调度原因，可能偏乐观；选号失败路径上的诊断日志体量也有待收敛。

## 部署

1. 从 Release 下载 `sub2api_2.3.157_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.157，页面入口资源哈希与后端一致。
- 对一个没有可用账号的分组发请求：503 的 `message` 只有固定短句，且服务端日志里能按 request id 找到完整诊断；请求不存在的模型得到 404，「当前可用」里没有分组白名单之外的别名。
- 管理端用量页：错误请求页的筛选面板约一半高度；未设置的筛选显示「全部…」；在「用户」里边输边出结果，点页面空白处或按 Esc 列表收起；搜一个不存在的邮箱出现「无匹配选项」；收起高级筛选后再搜用户，列表完整可滚动。
