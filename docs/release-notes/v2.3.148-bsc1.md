# 2.3.148-bsc1

> 热修版：只修 BSC 充值扫描游标冻结。基于 `v2.3.148` 加一个提交（#581），无数据库迁移、无其它改动。
> 只用于 crypto 扫描侧车（`CRYPTO_INSTANCE_ENABLED=true` 的那一个实例）；网关实例不需要换。

## 修复

- **分片锁态不再冻结充值扫描游标**：钱包 vault 迁到 v3 分片后，内存里没有 data key 是受支持的稳态（监控地址与充值地址分配都读经 MAC 认证的 DB 快照，扫入账区间不需要密钥）。此前 `scanWalletOutflows` 开头的安全检查把 `ErrSignerShareRequired` 当失败，每轮 deposit 的第一批区块都在 security 阶段失败，游标永远不推进（线上 BSC 停在 135294224，链每分钟长约 133 块，手动补扫也只是重复同一批失败）。
- 新增只用于充值扫描路径的守卫：仅把 `ErrSignerShareRequired`（分片锁态）视为成功；真正的安全事件（`status.Locked`）仍然阻断扫描，口径不变。
- `AuthorizedTokenTransfer` 在锁态下无法核对单笔流出时，跳过该笔判定而不是让整段区块失败；签名路径在没有密钥时仍独立拒绝广播。

## 升级与回滚

- 数据库迁移：无。
- 升级：只换扫描侧车的二进制（一次只动这一个 unit，用 `/usr/local/sbin/safe-restart-unit.sh`）。
- 验证：`crypto_scan_cursors` 里 `bsc` 的 `last_block` 与 `updated_at` 持续前进；日志里不再出现 `wallet signer is locked; a recovery shard is required` 导致的 cursor not advanced。
- 回滚：把侧车单元指回 `/opt/sub2api/candidates/2.3.148/sub2api` 后重启该 unit。
