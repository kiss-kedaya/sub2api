# Sub2API 2.3.64

## 归集状态卡死修复（链上已成功但后台一直显示失败）

- **根因**：确认流程读 `finalized` 标签时，端点不支持或返回非标准响应会让整次确认报错；错误走到 `pendingError` 分支，既不会重试到上限、也不会标记失败，记录永远停在 `sweep_pending`。同时真实原因被脱敏成一句通用文案，后台看不到细节。
- **修复**：
  - `finalized` 不可用时回退到按确认深度判定，确认继续推进；
  - receipt / canonical 判定改为有界多次、以正面证据为准，单个落后端点不会造成误判；
  - 结构化日志记录 `reason=finality_unavailable|canonical_mismatch|receipt_absent|rpc_failure` 与区块高度/深度（不含 URL 与密钥）。
- **自动补齐**：每轮归集开头只读链上核验，已确认的记录直接修正为 `swept`（条件更新，未证明的行不动，不签名、不广播）。

## 原生币扫描

- 默认改为「全块扫描 + 10 秒轮询」，txlist 作为后台可选的省调用方案；原生币出账纳入 `scanWalletOutflows` 告警。
