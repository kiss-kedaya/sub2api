# v2.3.169

本次是「降数据库压力 + 审计加固」版本：渠道监控的聚合任务不再每分钟把整小时的汇总数据删光重写，只写真正变化的行，数据库的写入量、写日志（WAL）和自动清理的压力明显下降；用量页的并发保护按用户分配名额，一个人刷新不会再挤掉别人，繁忙时页面保留旧数据并自动重试；另修了独立审计发现的几处小问题。**没有数据库迁移，没有接口字段和计费口径变化。**

## 亮点

- **渠道监控聚合任务只写变化的行**（#657）：监控页的聚合每分钟重算最近 2 分钟，并把窗口覆盖的 5 分钟 / 1 小时汇总桶「先整桶删除、再整桶重写」——其中绝大多数行的值根本没变，却每分钟制造约 2640 行插入 + 2640 行删除，让数据库的写日志、自动清理和索引膨胀一直处在高位。现在改成「重算后与表里现有内容比较」：表里有、重算结果里没有的才删；两边都有但值不同的才更新；只在重算结果里的才插入；值没变的行不更新、不加锁、不写日志。聚合口径一字未改，监控页的数字不变；事务边界、水位线、保留期清理都不变。本机用生产密度的数据（每分钟 9000 条请求）对比旧实现：每个聚合周期的行操作 24%、写日志字节 43%、耗时 42%、新增死元组 14%（折算到生产为估算，未经生产验证）。差分测试把旧实现原样冻结当对照，420 个周期 + 12 次范围重算，每次比较 8 张监控表和水位线逐行一致，覆盖 5 分钟 / 1 小时 / 12 小时 / 1 天桶边界、非 UTC 会话时区、进程重启、水位回拨补数、迟到写入、被删除或改写的来源行。
- **用量页并发保护按用户分配名额，繁忙时保留旧数据并自动重试**（#656）：之前整个进程只有 8 个「用量聚合」并发名额，任何一个人（或一个轮询 `/v1/usage` 的客户端）能占满，别人的用量页就报错。现在每个用户同时在库上跑的聚合有上限（默认 2 个，同一用户的其余聚合排自己的队，不占别人的名额；积压过多才直接拒绝）。名额用完时接口返回 **429 + `Retry-After: 2` + 错误码 `USAGE_STATS_BUSY`**（之前是 503、没有 `Retry-After`、每次都打错误日志、被计入 5xx 统计）；用量页遇到它时**保留已显示的图表和列表**，提示「统计繁忙，稍后自动重试」，按 `Retry-After` 自动重试一次，仍繁忙则提示「当前显示的是上一次的数据」，不再清空图表。用户列表的总数缓存键补上了用户 id（上线后这类总数各冷一次）。
- **账号窗口 / 用量采样写库的两处边角**（#656）：后台写入的闭包如果 panic，之前会让该账号同内容的写入被压制到 60 秒记账到期，现在会撤销记账、下一次立刻重试；429 限流路径等待后台写入没有上限，现在最长等一个写入超时 + 1 秒，超时后照常把「限流」状态落库。
- **失败记忆不再误记人为取消**（#656）：用量聚合失败后会记 30 秒避免反复重跑；现在只对「statement timeout」这类真超时记，运维取消查询或调用方取消不再被记成失败。
- **Responses Lite 请求体为 JSON `null` 时不再 panic**（#654）：旧代码就有的边角（被前置校验挡住、线上不可达），独立审计时发现，现在原样放行让上游拒绝。

## 变更清单

### 优化

- 渠道监控 v2 聚合：重算后差分同步，只写变化的行（#657）
- 用量聚合并发闸：每用户子配额、闸拒绝改 429 + Retry-After、日志限频、失败记忆只记 statement timeout（#656）

### 修复

- 账号窗口 / 被动用量后台写闭包 panic 后记账不撤销；429 路径等待后台写没有上限（#656）
- 用量页被并发闸拒绝时清空图表（#656）
- Responses Lite 归一化遇到 JSON `null` 会 panic（#654）

## 升级与兼容说明

- **数据库迁移**：无。可直接从 2.3.168 蓝绿替换，旧二进制可回退。
- **接口**：用量统计在并发名额用完时返回 429（`USAGE_STATS_BUSY`，带 `Retry-After`），原为 503；已打开的旧标签页在刷新到新前端之前，遇到 429 的表现与之前遇到 503 相同（按加载失败处理）；本版前端有变化，旧标签页会在几分钟内提示「发现新版本」，刷新后即为新行为。
- **蓝绿切换期间**：渠道监控聚合任务由持有 leader 锁的一个进程执行，新旧版本轮流执行时产出的表内容一致（差分测试覆盖）。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
