本版修复「上游正常返回、也扣了费，我们的使用记录却是 0 输入 0 输出、不计费」的问题。线上集中在 DeepSeek v4 flash。

## 修复

- **浮点 `created_at` 让整帧反序列化失败，用量被跳过。** 部分 OpenAI 兼容上游（实测 global-api.mysandbox.vip 的 deepseek-v4-flash）在 `response.completed` 事件里把 `created_at` 序列化成带小数的 JSON 数字，例如 `1790892388.0`。`/v1/messages` 和 `/v1/chat/completions` 的回程要把整帧反序列化成 `ResponsesStreamEvent`，而 `created_at` 是 `int64`，这一帧直接解失败，后面的用量解析被跳过。请求本身正常出字、耗时正常，使用记录记成 0 入 0 出、费用为 0。

  `/v1/responses` 直通用 gjson 按字段取值，不整帧反序列化，所以同一账号走这条路计费正常。

  现在 `created_at` 反序列化同时接受整数和浮点，回写给客户端仍是整数。用该上游的真实帧验证：改前报 `cannot unmarshal number 1790892388.0 into Go struct field of type int64`、用量 0；改后同一帧解出 5 入 10 出，与上游返回一致。

## 升级注意

- **数据库迁移：无。**
- 只改后端行为，前端产物无变化，无需重新构建前端。
- 按滚动方式部署：逐个实例换二进制并确认监听后，再切换下一台。
- 只影响本来会因浮点 `created_at` 解帧失败的请求；整数 `created_at` 的请求字节级不受影响。
