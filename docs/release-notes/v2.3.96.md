# 2.3.96

## 修复

- **账户概览、密钥用量页不再「暂时加载失败」**：按平台统计原来要回表读几百万行，20 秒超时后页面报错。新增两条覆盖索引（迁移 317，生产库已提前建好），统计接口平均耗时从 8 秒降到 1 秒左右；同一个统计在 60 秒内只查一次库，多人同时刷新、下游高频轮询 `/v1/usage` 不再把数据库读满。用量和费用类数字最多滞后约 1 分钟，余额、额度、限流仍是实时的。
- **数据库不再每分钟被整表扫描**：计费去重表（约 2.8 亿行）的归档任务在过期行不足一批时会顺序扫完整张表，超时后每分钟重来，磁盘读被顶满，统计类查询跟着变慢。现在按主键顺序取行，一批几十毫秒。
- **每天零点后分组用量汇总不再反复重建**：保留清理把汇总水位拉回 15 天前，汇总任务每 50 秒重建约 6000 万行并超时，持续数小时。现在清理先推进水位再删行，汇总同步的单条语句上限放宽到 5 分钟（迁移 316 恢复当天写入的免锁快路径）。
- **余额同步不再积压**：认领待同步余额变动的查询在统计信息刷新后会改成逐用户扫完整个索引，当天积压到 20 万条。查询计划现在不随统计信息变化。
- **没有别的号可选时不再报本站 503**：分组里唯一可用的号处于模型级短暂冷却时，请求被本站直接挡成「无可用账号」。现在会让这只号顶上，用户拿到的是上游的真实结果或真实错误；允许的那一次同号重试不会被冷却重选提前用掉，成功之后冷却立即解除。
- **缓存写入按上游报告的 5 分钟 / 1 小时分档计费**：OpenAI 兼容、Responses、Messages 转换以及 WebSocket、Gemini 兼容入口，以前上游明确报了 1 小时缓存写入也一律按 5 分钟单价收。现在按上游分档收；上游没报分档的请求和以前完全一样；分档不完整时差额按 5 分钟单价收；密钥设了强制 5 分钟计费时仍按 5 分钟。Anthropic 原生账号这条路的计费没有变化。
- **上游监控页恢复**：概览查询引用了不存在的列，整页刷不出来；倍率变化筛选传小数会报错；一只号的告警写入失败会丢掉所有号这一轮的采样。三处都已修。
- **首包暂存目录**：目录由别的用户先建出来时，网关写不进去会让流式请求持续失败。新建目录的权限改对，首选目录不可用期间直接使用系统临时目录，首包提交后及时释放暂存内存。
- **加密充值**：后台保存配置后扫描不再卡死（重载和旧扫描互相等锁）；各链可以单独配置扫描并发（付费节点可调高）；到账倍率、金额上下限、热钱包地址、自动归集开关的修改会同步到所有实例；充值页参考价读取不再与重载竞争。
- **节点状态页补扫**：扫描服务重启后补扫按钮不再被旧任务永久锁住；进度请求偶发失败会自动重试；节点状态接口失败时仍能看到已有补扫并取消。
- **导入到 CC Switch**：余额查询地址不再重复 `/v1`（Grok Build 等不再 404）；基础地址带查询参数时也能拉到模型列表。已导入过的旧配置需要重新导入一次。
- **渠道状态页**：新分组只有最近几次记录时，记录条贴着右边的 NOW 显示，左边留空，不再看起来像「以前可用、现在不可用」。

## 运维

- 发版前的前端完整性检查改为按构建清单逐个核对文件大小和校验值，能查出分包引用的分包、样式和字体缺失。
- 迁移执行器在建并发索引时不再受连接上的语句超时限制；建到一半留下的无效索引会自动重建。

## 升级注意

- 含迁移 316、317。317 在大表上要建两条索引；`usage_logs` 很大的库建议先手工并发建好同名索引再升级。
- 新旧版本混跑期间，旧版本的后台任务仍可能把汇总水位拉回，两台机器要一起切到新版本并停掉旧实例。
