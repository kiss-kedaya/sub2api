# v2.3.160

本次为「接口体验」版本：Base URL 怎么写都能请求成功、API Key 自己就能查自己的状态 / 分组倍率 / 用量、文档页新增「密钥与账号」分类。无数据库迁移，扫链代码无改动。

## 亮点

- **Base URL 带不带 `/v1`、写几个 `/v1`、末尾多一个 `/` 都能用**：Anthropic Messages、OpenAI Chat Completions、OpenAI Responses 三类文本模型接口，Base URL 写 `https://域名`、`https://域名/v1`，甚至 `https://域名/v1/v1`，都会到达同一个处理器、走同一套鉴权 / 限流 / 计费。以前缺少的是「多余的斜杠」：`/v1//chat/completions`、`//v1/chat/completions` 是 404，`/v1/chat/completions/` 是 307（多数 HTTP 客户端对 POST 不会跟随重定向）。现在这几种写法都会被整理成规范路径再路由；只有整理后命中已注册的网关路由才改写，面板页面、静态资源、`/health` 不受影响。首页「三步接入 API」的 curl 示例也不再多出一个 `/v1`。（#612）
- **用 API Key 就能查「这把 Key」的信息**：三个只读接口，Bearer 或 `x-api-key` 都行。（#613）
  - `GET /v1/sub2api/key`：这把 Key 的状态、**是否可用以及不可用的原因**（过期 / 额度用完 / 停用 / 没有分组 / 分组不可用）、到期时间、额度已用与剩余、5 小时 / 1 天 / 7 天限速窗口与重置时间、绑定的分组（按路由顺序）。
  - `GET /v1/sub2api/groups`：这把 Key 已路由的分组，加上该用户还能绑定的分组；每个分组给出状态、基础倍率、用户专属倍率、**此刻实际生效的倍率**（含高峰倍率）。
  - `GET /v1/sub2api/usage`：这把 Key 的今日 / 近 7 天 / 本月 / 自选区间（`start_date`、`end_date`，格式 `YYYY-MM-DD`，跨度不超过 90 天）用量，可选 `daily=1` 返回按日序列、`timezone` 指定时区；某个统计块没算出来时在 `partial` 里点名，不会当成 0 返回。
- **文档页新增「密钥与账号」分类**：写清上面三个接口（字段、示例、限制）和控制台里「用户创建密钥」相关的会话鉴权接口（创建、列表、更新、分组、错误处理）；接口旁有徽标区分「API Key」与「登录会话」两种鉴权；侧边栏当前条目自动滚入可视区，下面还有内容时给出渐隐提示；代码块页签点击区不小于 36px。（#614）

## 变更清单

### 新增

- `GET /v1/sub2api/key`、`GET /v1/sub2api/groups`、`GET /v1/sub2api/usage`（#613）
- 文档页「密钥与账号」分类，含 `key-self-service`、`manage-keys` 两页（#614）
- 网关路径别名层：整理多余斜杠（#612）

### 优化

- 首页 curl 示例与 `base_url` 都由同一个函数从「站点根」拼出，只出现一次 `/v1`（#612）
- 文档页侧边栏与代码块的可用性（#614）

### 修复

- 首页接入示例出现 `/v1/v1/chat/completions`（#612）
- Base URL 末尾带斜杠、或 SDK 再拼 `/v1/...` 后出现双斜杠时请求 404 / 307（#612）

## 升级与兼容说明

- **数据库迁移**：无。
- **新接口的暴露面**：只回答「这把 Key 是什么、做过什么」。不返回 Key 明文或哈希（只有展示用前缀）、IP 白 / 黑名单、最后使用 IP、钱包余额、订阅余额、账号 / 渠道 / 上游名称、账号成本。现有 `/v1/usage`（兼容接口）行为不变。
- **新接口的鉴权与计费语义**：只做鉴权、不做计费检查，所以过期或额度用完的 Key 也能查询并看到原因；已停用的 Key、被停用的属主、不在 IP 白名单内的请求仍按原规则拒绝。查询不更新 `last_used_at`，状态轮询不会掩盖真实使用。
- **新接口的限流**：每把 Key、每个接口每分钟 30 次（Redis 固定窗口，三个接口各自计数）。超出返回 `429`，带 `Retry-After` 与 `{"error":{"code":"key_info_rate_limited"}}`，并标记为客户端限流，不计入网关错误率。Redis 出错时放行；没有 Redis 时不限流。30 次 / 分钟对「状态栏每 5 秒轮询一次」（12 次 / 分钟）很宽松。
- **缓存**：分组目录与「用户可绑定分组」在进程内缓存 20 秒；用量汇总复用现有 60 秒统计缓存。
- **自行部署的反向代理**：如果你的 nginx 里对裸 `/chat/completions`（不带 `/v1`）写了直接返回 400 的规则，请改成与其它网关路径一致的转发，后端会自己补 `/v1`；仓库里 `deploy/nginx/sub2api-backend-locations.conf` 的模板本来就是转发，无需改动。
- **页面刷新**：本版前端文件有变化，已打开的旧标签页会在几分钟内提示「发现新版本」。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 路径里的大小写不折叠：`/V1/…` 仍是 404，因为路径里的模型 ID 区分大小写。
- 新接口没有返回钱包 / 订阅余额，这是有意的最小暴露；需要时另行设计（连同是否收紧现有 `/v1/usage`）。
- 使用记录页的「模型分布」「端点分布」冷查询仍需回表（沿用 2.3.159 的已知问题，需要表结构改动，单独讨论）。

## 部署

1. 从 Release 下载 `sub2api_2.3.160_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.160，首页注入的 `window.__APP_CONFIG__.version` 也是 2.3.160，页面入口资源哈希与后端一致。
- 首页「三步接入 API」里的 curl 是 `…/v1/chat/completions`，只有一个 `/v1`。
- 用一把真实 Key，对三类接口（`/v1/messages`、`/v1/chat/completions`、`/v1/responses`）分别用 `https://域名`、`https://域名/v1`、`https://域名/v1/v1`、末尾多一个 `/` 的 Base URL 各请求一次，都应成功（鉴权失败是 401，不是 404 / 307 / 400）。
- `curl -H "Authorization: Bearer $API_KEY" https://域名/v1/sub2api/key`：返回 `"object":"sub2api.key"`，有 `is_usable`；响应里没有 Key 明文、IP、余额字样。`/v1/sub2api/groups`、`/v1/sub2api/usage?daily=1` 同理，`usage` 的 `today` / `last_7_days` / `this_month` 三块都有数字。
- 同一把 Key 连续请求同一个接口，第 31 次起 `429` 并带 `Retry-After`；换一个接口或换一把 Key 不受影响。
- 日期区间校验：`start_date` 晚于 `end_date`、格式不对、跨度超过 90 天，都是 `400`。
- 打开 `/docs`：侧边栏出现「密钥与账号」，进去能看到两页；当前条目在可视区内，下方还有内容时有渐隐提示。
