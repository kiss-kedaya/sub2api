本版修一处会让整个请求被上游拒掉的 Grok 参数问题。

## 修复

- **Grok 的 `max_output_tokens` 超过模型上限时改为夹取，不再让上游拒掉整个请求。** 客户端若申请了超过模型允许的输出预算，上游会直接以 400 拒绝，错误为 `Field 'max_output_tokens' must be at most 128000`——**尽管请求的其余部分完全正常**。线上实测该错误 6 小时内 48 次（账号 30767 / platform grok / `/v1/responses`），全部由客户端带入的超限值触发。现在在 Grok Responses 的请求体补丁链上把该值夹到上限，与既有的 Ollama Cloud 夹取保持同一形态。

  夹取**只作用于真正超限的数值**，边界行为如下：字段不存在时**不会凭空添加**（不替客户端决定输出预算）；等于或低于上限时保持原样；非数字值原样交给上游判定，不做改写。

  ⚠️ **已知局限**：上限取的是上游报出的 128000，是**模型无关**的。若某个 Grok 模型的真实上限更低，夹到 128000 仍会被拒——那种情况需要按模型细化，或改成按账号配置（参照 `ollamaCloudMaxTokensCap` 的做法）。这一点写在该常量的注释里。
