# 2.3.138

## 支付 / 到账（本版重点）

- **修复「支付成功但订单卡在充值中」**：支付回调的履约链路（置 PAID → 建履约码 → 加余额 → 返佣 → 置 COMPLETED → 审计）此前贯穿 HTTP 请求上下文。回调方超时或断开时事务被一起取消（生产日志 `mark FAILED / context canceled`），订单停在 RECHARGING、余额未加。
- 资金动作改为脱离请求的独立上下文（`context.WithoutCancel` + 30s 独立预算），客户端连接生命周期不再影响入账；验签、查单等 PAID 之前的可重试动作仍用请求上下文。
- **卡单自动补偿**：复用订单过期服务的 60 秒 tick + leader lock，扫描 `paid_at` 非空、状态为 PAID/RECHARGING/FAILED 且超过 2 分钟未完成的订单重新履约。幂等由租约 CAS、确定性履约码「已用即跳过」、COMPLETED 短路保证，重复执行不会二次入账；失败最多重试 5 次，成功写 `ORDER_FULFILLMENT_RECOVERED` 审计（原状态、卡住时长、恢复耗时、次数）。

## 兼容性

- 修复 `/v1/messages` 入口未剥离 Claude Code 客户端上下文后缀（如 `gpt-6-astra[1M]`）导致上游 400/404「模型不存在」的问题；`/v1/chat/completions` 路径行为不变。

## 仪表盘

- 刷新延迟窗口内保留已关闭的 rollup 数据，避免图表在刷新间隙出现空洞。

## 运维 / 磁盘
