# v2.1.3

- claude-opus-5-5 的 `/v1/messages` 不再把非法参数修好后再转发。缺 `max_tokens`、`temperature` 越界、`type=text` 没带 `text`、`messages` 缺失或空数组，一律直接 400，错误体是 Anthropic 格式（`error.type` 为 `invalid_request_error`）。开 `thinking` 时同时传非默认 `temperature` / `top_p` / `top_k` 同样 400，不再静默删掉采样参数。Anthropic 与 OpenAI 两个 `/v1/messages` 入口口径一致。
- Gemini `/v1beta/models` 不再用内置全量目录合成模型列表。分组里放了 OpenAI 平台类型账号时，以前会返回一大截跑不了的模型；现在本地目录只来自账号真实映射，上游获取失败时直接透传上游响应（含错误码），不再伪造 200 空目录。
- 使用记录的请求 ID 搜索不再拖慢后台。`usage_logs` 补上 pg_trgm 索引（迁移 256a / 256b），搜索词里的 `%` `_` 会被转义，不再因为一个下划线就扫全表。按 `client:` 前缀或上游请求 ID 片段搜索照常可用。
- 在途请求与已结束请求不再重复显示。同一条请求以前会在「在途」和「已记录」各出一行，一直挂到过期；现在两侧用同一个请求 ID 比对。
- 网关不再把合法的 S3 预签名回链、SigV4 调用方当成扫描器封 IP（此前会返回 404 并把来源 IP 写进 24 小时封禁表）。扫描器特征路径的拦截保持不变。
- 用量明细里的复制按钮在 HTTP（IP 直连）下也能用了。以前 `navigator.clipboard` 在非安全上下文不存在，点了没反应且控制台无输出。

新增数据库迁移 256a / 256b（`usage_logs` 的 pg_trgm GIN 索引，CONCURRENTLY）。生产环境保持 `validate`，部署时单独执行迁移。余额预扣 hold 仍默认关。二进制可回滚到 2.1.2；迁移只加索引，回滚后旧二进制照常启动。
