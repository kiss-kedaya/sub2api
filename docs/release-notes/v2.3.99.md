# 2.3.99

## 修复

- **报错信息里不再带出上游中转的特征**：上游是第三方中转时，它自己生成的报错会带专有的
  错误类型名（`new_api_error` / `one_api_error`）和请求号后缀 `(request id: …)`。
  - DeepSeek 语音识别 / 语音合成 / 文档识别、搜索 / 抓取这些直通错误体的接口：专有类型名换成
    按状态码的标准类型（400 → `invalid_request_error`、401 → `authentication_error`、
    403 → `permission_error`、404 → `not_found_error`、429 → `rate_limit_error`、5xx → `api_error`），
    末尾的请求号后缀去掉。
  - 聊天、Responses、Messages 等重新包装报错的接口：报错文字末尾的请求号后缀去掉。
  - 报错正文、HTTP 状态码、官方格式的 `(request_id: …)` 都不变；不带这两样特征的报错逐字节不变。
  - 后台运维日志里仍然保留上游原文和请求号，对账用后台看。

## 升级注意

- 无数据库迁移，无前端改动。
- Antigravity 上游直通的流式响应没有做这项处理。
