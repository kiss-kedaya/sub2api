本版补上 2.0.38 没覆盖的下游兼容。2.0.38 修的是我们自己的计费：上游把 `created_at` 写成浮点时，我们的回程解帧失败、用量记成 0。但 `/v1/responses` 透传是字节级转发，浮点会原样到下游。下游若是官方版，`created_at` 是裸 `int64`，同样整帧解失败、用量记成 0。

## 修复

- **透传给下游前，把浮点 `created_at` 收成整数。** 流式透传、非流式透传、SSE 转 JSON 三条写出路径都在写出前处理。只改带小数点的数字（`1790892388.0` → `1790892388`），整数原样不动，`usage` 等其他字段不改。

  这样下游无论是官方版还是我们的版本，收到的 `created_at` 都是整数，不会再因这个字段解帧失败。

- 无。

## 升级注意

- **数据库迁移：无。**
- 只改后端行为，前端产物无变化，无需重新构建前端。
- 按滚动方式部署：逐个实例换二进制并确认监听后，再切换下一台。
- 整数 `created_at` 的请求字节级不受影响。
