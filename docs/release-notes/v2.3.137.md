# 2.3.137

## 管理端 2FA 体验（本轮重点）

- 修「只读接口误要求二次验证」（#507）：`/admin/proxies` 列表/详情、账号今日统计与 usage 批量、上游渠道列表等**只读**接口不再要求 step-up；真正返秘密的读（凭据回读、整表导出、备份下载、debug dump、用户/分组 API Key、卡密/优惠码明文、代理明文导出 `proxies/data`）与全部写操作继续强制二次验证。
- 前端「静默读」机制：页面加载/后台自动请求命中 403 时**不再弹 TOTP**、不再刷 `StepUpCancelledError`，改为占位「该数据需二次验证后查看」；只有用户主动点击的敏感按钮才弹码。
- 新增防复发机制：只读 GET 若要求 step-up 必须写明具体秘密字段，否则 CI 直接失败。

## 支付 / 充值体验

- 充值页网络延迟提示改为按「链上时间」判定（#503）：BSC 落后 ≤5 分钟（约 100 块）不再提示；5–30 分钟只给「网络确认较慢」的中性说明；>30 分钟才提示到账延迟。

## Codex / Responses API

- 修复 Codex Desktop / IDE 页面上下文被误判为「缺少 call_id 的工具输出」导致整单 400（#502，上游 issue #8609）：无 call_id 的 `namespace=agent` 上下文还原为普通输入；错误提示改为可操作中文；WebSocket v2 路径不变。

## 计费一致性

- 余额变更 outbox 水位冲突可自愈（#506）：此前累积 200 万+ 条未投递行（346 个用户），导致这些用户数据库余额正确但页面显示滞后；新版本按数据库权威余额重建水位并重放，不再无限重试。
- 风控自动停用 Key 写入 `audit_logs`（#505），可追溯。

## 安全 / 数据

- 第三方登录身份默认停止明文双写（#504）：只写 keyed HMAC 哈希与前缀；读取哈希优先 + 明文回退，登录绑定不受影响。历史 14,500 条已回填校验，明文清理由后续操作阶段执行。

## 说明

- 无新增数据库迁移。
- 回滚：蓝绿切回 2.3.136；本版无不可逆数据变更。
