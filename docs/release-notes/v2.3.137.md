# 2.3.137

## 支付 / 充值体验

- 充值页网络延迟提示改为按「链上时间」判定（#503）：BSC 落后 ≤5 分钟（约 100 块）不再提示；5–30 分钟只给「网络确认较慢」的中性说明；>30 分钟才提示到账延迟；扫描异常仍有独立提示。此前落后几十个块就会误报「可能延迟」。

## Codex / Responses API

- 修复 Codex Desktop / IDE 的页面上下文被误判为「缺少 call_id 的工具输出」导致整单 400 的问题（#502，对应上游 issue #8609）：识别 `namespace=agent` 的无 call_id 上下文并还原为普通输入文本；未识别条目与真实工具输出不受影响；错误提示改为可操作的中文说明，不再误指「HTTP 不支持 previous_response_id 续传」。WebSocket v2 路径不变。

## 计费一致性

- 余额变更 outbox 水位冲突可自愈（#506）：此前 `live_balance_adjustment_outbox` 累积 200 万+ 条未投递行（346 个用户），导致这些用户数据库余额正确但页面余额显示滞后。新版本在检测到水位冲突时按数据库权威余额重建水位并重放，且不再无限重试卡死。
- 风控自动停用 Key 时写入 `audit_logs`（#505），可在后台追溯「因 IP 共用被自动停用」的 Key。

## 安全 / 数据

- 第三方登录身份（GitHub / Google / 邮箱等）默认停止明文双写（#504）：只写 keyed HMAC 哈希与前缀；读取保持哈希优先 + 明文回退，登录与绑定不受影响。生产历史 14,500 条已完成回填与全量校验，明文清理由后续操作阶段执行。
- 管理端 2FA 门控延续 2.3.136 的「默认拒绝机器凭据 + 敏感资源强制 step-up」；本版不含路由分类调整（只读接口误要求二次验证的修复在下一版）。

## 说明

- 无新增数据库迁移。
- 回滚：直接蓝绿切回 2.3.136；本轮无数据不可逆变更。
