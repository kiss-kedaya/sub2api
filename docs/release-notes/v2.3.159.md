# v2.3.159

本次为「体验与速度」版本：余额自动刷新、创建密钥不再强制输登录密码、密钥回执弹窗改成安静版、使用记录页加载提速，并带一处 Claude 计费锚点校正。无数据库迁移，扫链代码无改动。

## 亮点

- **余额自己会刷新**：顶栏余额在切回标签页、窗口重新获得焦点时立刻刷新一次；后台再随机 1–10 分钟刷新一次（原来固定 90 秒，且只在页面可见时）。余额框带呼吸灯边框：请求发出时主题色快速闪烁，请求结束后变成淡绿色缓慢呼吸，最近一次刷新失败时不亮环（不假装数字是新的）。`prefers-reduced-motion` 下不闪不呼吸，只保留静态的环。（#607）
- **创建 / 轮换密钥不再强制输入登录密码**：只有开了 TOTP 或绑定了 Passkey 的账号才强制校验。用 Google / GitHub 登录、不记得登录密码的用户可以直接创建；没有校验因子的账号，创建弹窗只有一步，没有步骤头和密码框。更新前打开的旧页面如果带着密码来，错的照样拒绝（`VERIFY_PASSWORD_INVALID`）。（#603）
- **创建后的密钥回执弹窗改成安静版**：文字大幅减少，用图标说话，标题下只留一句「仅显示一次，请立即复制保存」。创建时已经输过登录密码的，回执里打开「以后可查看」不再要求再输一遍（密码只放内存、关闭回执即清空，被服务端拒绝时退回手输）；没有本地登录密码的账号，这一行整个不显示。（#608）
- **使用记录页加载提速**：统计卡片和「端点分布」拆成两个请求，卡片先出；首次加载显示占位而不是 0，刷新时保留旧数字并变淡。用户端聚合不再计算用户看不到的账号成本两列，数据库得以只读索引；分组分布加 60 秒缓存；带筛选翻页时列表总数按筛选缓存 60 秒（管理端不变）。（#610）
- **页面过期后的整页刷新更克制**：同一页面里只改查询串 / 锚点（切标签页、改筛选）不再触发整页重载，换页面才整页加载。（#602）
- **渠道状态**：时间线上方「缓存率 < 30% 视为不可用（黑格）」的说明行去掉，格子本身不变。（#604）
- **Claude 计费锚点校正**：非 Anthropic 分组为 Claude 族计费模型配了供应商目录价时，改按 Claude 官方价和承载 Claude 的分组倍率计费；不满足触发条件的请求（Anthropic 分组、非 Claude 模型、分组没为该模型配价卡）计费结果不变。Grok 分组经 messages 分发收到 `claude-*` 名字时，名字先映射成该分组自己的 Grok 模型，计费按实际服务的 Grok 模型，行为不变，并已用测试固定。（#605、#609）

## 变更清单

### 新增

- 余额回到页面即刷新、后台随机刷新、余额框呼吸灯（#607）
- `GET /api/v1/usage/stats` 新增 `scope=summary|endpoints`，不带 scope 行为不变，非法 scope 返回 400（#610）
- 验证因子接口新增 `create_verification_required`（#603）
- 密钥回执弹窗的一行式「以后可查看」开关（#608）

### 优化

- 使用记录页：卡片先出、分组聚合与翻页总数缓存（#610）
- 创建 / 轮换密钥只在开了 TOTP / Passkey 时强制校验（#603）
- 页面过期后同页改查询串不再整页重载（#602）

### 修复

- 批量轮换对没有校验因子的账号先开了「验证身份」对话框且从不关闭（#603）
- Claude 族计费模型被非 Anthropic 分组按供应商目录价结算（#605）

### 其它

- 渠道状态去掉缓存率说明行（#604）
- 测试与注释：固定 Grok 分组 messages 分发按实际服务的模型计费（#609）

## 升级与兼容说明

- **数据库迁移**：无。
- **创建密钥的新规则**：以前「会话被劫持就能静默建 Key」靠创建时的登录密码挡着；现在只有登录密码的账号靠登录本身的防护（登录风控、Turnstile、会话有效期），开了 TOTP / Passkey 的账号保持原样。老前端拿不到 `create_verification_required` 时退回「有任何可用因子就强制」，滚动发版期间新页面碰到旧实例不会少带校验材料。要改回更严的口径，把后端 `CreateVerificationRequired` 的取值改成「有任何可用因子就为 true」。
- **余额轮询变稀**：原来页面可见时 90 秒一次，现在 1–10 分钟随机（平均 5.5 分钟）加「回到页面立刻刷新」。一个一直摆着不切换的页面，余额最多晚 10 分钟；要让前台更勤，只改前端常量 `AUTO_REFRESH_MAX_DELAY`。
- **缓存**：用户端分组聚合和列表总数在 Redis 里缓存 60 秒，同一筛选下新产生的请求最多晚 60 秒计入总数；管理端和带 `ExactTotal` 的调用仍实时。
- **页面刷新**：本版前端文件有变化，2.3.158 起打开的旧标签页会在几分钟内提示「发现新版本」；更早打开的页面没有探测代码，仍需手动强制刷新一次。
- **crypto 侧车**：本版没有改动扫链代码，侧车保持 2.3.155 即可，不必更换。
- **上线后仍需人工确认**（沿用 2.3.154）：`gateway_5xx` 告警规则被迁移 339 禁用后，需在后台按新口径重设阈值并重新启用。

## 已知问题（不阻塞本版，后续处理）

- 使用记录页的「模型分布」「端点分布」仍要读每一行的模型 / 端点文本，这两列不在覆盖索引里，宽窗口的冷查询仍需回表；它们不再拖住统计卡片，并且有 60 秒缓存。要根治需要给 `usage_logs` 加索引列，或扩大汇总表对「近 24 小时」这类非整点窗口的覆盖，涉及表结构，单独讨论。
- Claude 模型准入闸门（#605 新增的 `claudeModelAdmission`）目前没有生产调用方，不改变任何路由结果；`groupPassthroughsRequestedModel` 里 #605 加的 claude 例外分支也不可达。两处在 #609 里已标注，删掉还是接入调度留待维护者决定。

## 部署

1. 从 Release 下载 `sub2api_2.3.159_linux_amd64.tar.gz` 与 `checksums.txt`，先 `sha256sum -c checksums.txt`。
2. 新二进制执行 `-check-migrations`（本版预期没有待执行迁移）。
3. 蓝绿部署：新端口启动新实例，`/health` 与首页 200 后先接 1% 流量，观察错误率与日志再放量；nginx 里写死 upstream 的路由族（固定池）要一起改指新端口。选新端口时用 `ss -tan` 查任意状态，别只看监听（出站连接的源端口可能恰好等于候选端口）。
4. 旧实例保留至新版本稳定，回滚只需把流量切回上一版端口。

## 验证清单

- 首页与 `/api/v1/settings/public` 版本号为 2.3.159，首页注入的 `window.__APP_CONFIG__.version` 也是 2.3.159，页面入口资源哈希与后端一致。
- 顶栏余额：切到别的标签页再切回来，余额框闪一下后变成淡绿色呼吸，数字是最新的；不需要刷新整个页面。
- 使用记录页：打开后四张统计卡片先显示占位（不是 0），随后数字先出现，端点分布最后出现；换一个分组筛选、翻页都明显比以前快。
- 用户中心 → API 密钥 → 创建（没开 TOTP / Passkey 的账号）：只有一步，填完名称和分组直接创建；回执弹窗里打开「以后可查看」不再要求再输登录密码。
- 开了 TOTP 或 Passkey 的账号创建密钥：仍然要走校验步骤。
- Grok 分组的 Key 经 `/v1/messages` 请求 `claude-*`：使用记录里 `model` 是 claude 名、`upstream_model` 是该分组的 Grok 模型，按 Grok 模型计价和分组倍率扣费。
