- 修复客户端工具 schema 根级 `oneOf`/`anyOf`/`allOf` 被上游拒绝的问题：Anthropic 只接受 object 根节点，部分客户端内置工具（如 codex_app 的 automation_update）会把参数根声明成对象分支的联合，此前 `/v1/responses → /v1/messages` 会直接 400、整轮失败。现在转换时摊平为单个 object schema：属性取各分支并集，同名属性用嵌套联合保留两侧约束，`required` 在 `oneOf`/`anyOf` 下取分支交集、`allOf` 下取并集；嵌套层的联合保持不变。
- 修复工具参数丢失导致「工具无法调用」：部分 Anthropic 兼容中转会把完整工具参数放在 `content_block_start` 上并从此不再发送增量，此前这类请求返回给客户端的工具调用参数为空字符串。现在会把它们作为种子暂存，若随后有真实增量则以增量为准，若始终没有增量则在块结束时补发一次。
- 修复工具 schema 里非法的 `required: null` 被严格校验的上游拒绝（400）：JSON Schema 要求该字段是数组，缺省与空数组语义等价，因此直接删除该成员。同时让 Anthropic Messages 的 `input_schema` 也走同一套清洗，并补充 `contentSchema` 子节点。
- Grok：函数工具的参数根若是「含非 object 分支的联合」，改用宽松 object schema 并把 `strict` 放宽，避免上游 400；带无法解析 `$ref` 的联合保持原样不动——把它降级成空对象会悄悄改变工具契约。
- Antigravity / Gemini：同步 schema 清洗逻辑，支持 `prefixItems` 元组定义（摊平成单一 `items`）、`const` 规范化为 `enum`、以及缺少 `items` 的数组补默认 schema，避免上游 400。
- Antigravity：内置搜索工具与客户端 function 工具混用时不再整单失败。v1internal 不支持两者混用（设置了 includeServerSideToolInvocations 也会 400），而 Codex 默认同时携带搜索与 shell 等工具；现在优先保留客户端工具并丢弃内置工具，也不再为此强制切换到 web_search 降级模型。
- Antigravity：上游因工具调用畸形返回 `MALFORMED_FUNCTION_CALL` 时会产生「只有结束事件、没有任何内容」的空流，此前被当作有效输出，客户端拿到的是「成功但没有输出」——工具调用会凭空消失。现在这类流会触发重试与故障转移。
- Chat Completions → Responses 转换中的角色消息补上显式的 `type: message`，避免下游按条目类型判定时出现异常。
- 工具名改写改为按偏移一次性成批处理，避免逐次改写时的重复序列化。
