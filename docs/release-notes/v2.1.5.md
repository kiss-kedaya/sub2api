# v2.1.5

- 修掉密钥级「强制 1h 缓存」至今不生效的最后一处根因。鉴权查询 `GetByKeyForAuth` 用的是一份逐列写死的最小字段投影，里面从来没有 `anthropic_cache_ttl_mode` 这一列 —— 网关热路径读到的 `AnthropicCacheTTLMode` 恒为空字符串，归一化成 `inherit`，而 `inherit` 分支只对 Anthropic OAuth 账号生效，于是 API-key 账号上的 TTL 改写整段不执行。表现为后台能看到设置、`usage_logs.cache_ttl_overridden` 恒为 `f`、建出来的缓存全是 5m，且全程没有任何报错。

  v2.1.4 补的两处（透传分支早退、API-key 出站缺 `extended-cache-ttl-2025-04-11` beta）都是真实缺陷，但拿到的 mode 永远是 `inherit`，所以单靠它们不够。本次补上投影列，并加集成测试守住（同 fast / model_allowlist / profit 三处已有投影测试同一口径）。

- v2.1.4 已包含：收到上游终止事件后不再空等 body 关闭（释放并发槽、避免把成功请求记成 idle timeout）、`gateway.stream_data_interval_timeout` 上限从 300 放宽到 3600 秒。

无新增数据库迁移。余额预扣 hold 仍默认关，生产 `DATABASE_MIGRATION_MODE` 保持 `validate`。鉴权快照版本常量未变，Redis 里的老快照缺该 json 字段会解析成 `inherit`，与修复前行为一致，L2 缓存 300 秒内自然轮换，无需清缓存。二进制可回滚到 2.1.4。
