- 新增计费看门狗：在既有运维告警里增加 5 个**只读**计费指标，用于第一时间发现计费异常并邮件通知——`billing_zero_cost_requests` / `billing_zero_cost_ratio`（有 token 用量但实际扣费为 0，即「用了不扣费」）、`billing_negative_balance_users`（余额被扣成负数的用户数）、`billing_cost_spike_ratio`（本窗总扣费相对上一个等长窗口的倍数）、`billing_stuck_holds`（已过预扣有效期却从未结算的笔数，持续增长说明预扣泄漏）。这些指标**只做聚合查询，不会修改余额、预扣或用量的任何一行**，也不在请求链路上执行，因此不可能影响计费本身。查询全部走时间索引且窗口有上限，避免在用量表很大时拖慢告警评估。
- 新增部署一致性检查：由主机侧定时核对**实际在运行的二进制**（按监听端口定位进程后读 `/proc/<pid>/exe`，而不是相信单元名）与单元 `ExecStart` 是否等于期望版本，结论写入状态文件后由 `deploy_version_mismatch` / `deploy_check_age_seconds` 两个指标暴露并复用同一套邮件告警。此前的故障形态是「单元名写着一个版本、进程实际跑着另一个版本」，导致相当一部分流量长期缺少修复；这类问题在进程内部无法自检，只能放在主机层。状态文件缺失、损坏或过旧时指标一律为「不可用」而**不会报成正常**，看门狗自身停摆则由 `deploy_check_age_seconds` 报告。
- 安全加固：统一并收紧出站目标解析后的 IP 封禁清单。此前一处校验只依赖标准库的私网/回环判定，漏掉了 CGNAT（`100.64.0.0/10`，云厂商元数据服务所在段）、`198.18.0.0/15`、`240.0.0.0/4`、全局组播 `224.0.0.0/4` 以及若干文档/过渡段，而仓库另一处校验的清单是完整的——两份口径不一致。现在合并为单一来源并被两处共用，改动方向为纯收紧。
- 运维告警新增「计费看门狗指标」与「部署一致性指标」两个分组，中英文均已补齐，可在管理端「预警规则」里直接配置阈值与通知。
