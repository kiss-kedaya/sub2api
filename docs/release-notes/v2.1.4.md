# v2.1.4

- 密钥级的「强制 1h 缓存」以前对 Anthropic API-key 账号完全没生效，缓存一直按 5m 建。两个根因叠加：一是透传账号（`extra.anthropic_passthrough=true`）在 `Forward` 里提前返回，密钥级 TTL 改写那段代码根本执行不到；二是 API-key 账号的出站 `anthropic-beta` 从来不包含 `extended-cache-ttl-2025-04-11`，上游缺这个 token 不报错，而是静默降级成 5m 建缓存。现在两条路径都会按 body 里是否真有 `ttl:"1h"` 断点补齐 beta，透传分支也会执行密钥级 TTL 改写。只做加法：没有 1h 断点的请求一个字节都不动；管理员 beta 策略里明确要丢这个 token 时仍尊重策略。
- 上游已经发出终止事件（`message_delta` / `[DONE]`）并带完 usage 后，网关不再等对方关闭 HTTP body。此前只有 Grok 平台会在这个时刻收尾，其它平台会一直等到 body 关闭或间隔超时，表现为账号并发槽被占住不放、用户侧像卡住不出字、成功请求被记成 idle timeout、已完成请求迟迟不结算。现在两类入口统一按终止事件收尾，usage 与断连标记照常返回，不会漏计费。
- `gateway.stream_data_interval_timeout` 上限从 300 放宽到 3600 秒。长思考模型（如 opus-5-5 配 `effort=high`）单次间隔可能超过 5 分钟，上限太低会把正常流误杀成超时。
- 测试夹具与业务代码注释里出现过真实上游域名（历史遗留：写测试时直接照抄了生产错误日志的报错原文）。已全部替换为 `example.com` 占位符，逻辑与断言语义不变。同时把本地经验、审计记录、监控栈配置加进 `.gitignore` —— 这些文件此前只在本地 `.git/info/exclude` 里排除，换台机器 clone 或新建 worktree 时不受保护。

无新增数据库迁移。余额预扣 hold 仍默认关，生产 `DATABASE_MIGRATION_MODE` 保持 `validate`。二进制可回滚到 2.1.3。
