# v2.2.3

补齐 Grok 安全拒绝在 raw 路径上的扣费，并把扣费口径改为「名义价 × 组倍率」。

## 1. 问题

Grok 上游内容策略拒绝返回：

```
I'm sorry, I can't help with that request. Failed check: SAFETY_CHECK_TYPE
```

已有逻辑只挂在 Anthropic 平台的 `/v1/messages`、`/v1/chat/completions` handler 的
`UpstreamFailoverError` 分支上。但 Grok 分组实际走 OpenAI 网关，且有 97% 的请求
落在 `forwardAsRawChatCompletions`：该路径把 403 当普通错误，经
`handleCompatErrorResponse` 直接回写，不产生 `UpstreamFailoverError`，因此完全
不进扣费分支。

7 天实测：安全拒绝 7,721 次，真正扣费的只有约 16 次；24 小时内 `/v1/chat/completions`
共 1,400 次拒绝，扣费 0 次。

## 2. 修复

- 新增 `IsGrokPlatformContentPolicyRejection`：从 `handleCompatErrorResponse` 返回的
  `grok content policy rejection:` 前缀识别该分支。
- OpenAI 网关 handler 在该错误分支补扣费，并封禁同一会话 24 小时，避免同一提示词
  反复消耗上游额度。
- `OpenAIForwardResult` 增加 `ForcedBillingCost` / `ForceBalanceBilling` 两个字段，
  与 Anthropic 侧的同名语义对齐；`openai_gateway_usage.go` 在计费入口按强制费用
  覆盖 usage 成本，并跳过订阅计费。
- 新增 `OpenAIGatewayService.BlockModerationRefusedSessionForOpenAI`，使用该服务自己的
  `GatewayCache` 执行会话封禁。

## 3. 扣费口径

改为 `0.1 × 组/用户倍率`，与 token 计费一致：

| 组倍率 | 每次拒绝实扣 |
|---|---|
| 1.00x | 0.100 |
| 0.14x | 0.014 |
| 0.07x | 0.007 |
| 0 | 0 |

倍率解析沿用 `ResolveUserGroupRateMultiplier`（用户专属 > 分组默认 > 系统默认），
不额外叠加高峰因子——高峰因子只在 token 计费里随请求时刻变动，违规拒绝按结算时
的组倍率执行。

## 4. 验证

- 单测覆盖：倍率换算（含 0 与负数）、OpenAI 结果构造、内容策略错误识别、
  非 Grok 平台与非相关错误不误判。
- `go build ./...`、`go vet ./internal/service/ ./internal/handler/`、
  `go test ./internal/handler/`、`go test ./internal/service/` 全量通过。

无数据库迁移。
