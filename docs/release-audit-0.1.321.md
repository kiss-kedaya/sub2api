# 0.1.321 最小输入策略与渠道健康

日期：2026-09-16。前一版本320已经双机全量并保留319热备。

## 修复依据

- 用户提供稳定高缓组账号28659的上游400：`error.code=input_too_small`，要求输入至少2000 token。该请求不符合上游使用条件，不能代表渠道故障。
- 原始记录的type为 `invalid_request_error`，渠道统计按invalid_request计错，当前配置未忽略该类。没有把全部400或全部invalid_request隐藏。
- 旧318/319/320热备仍运行被动统计器，只修改新统计器会被旧工作进程反复重算。因此在日志入队前将精确代码对应的诊断摘要加上统一长度策略标签，复用现有context_limit分类和已启用的忽略规则。
- 仅命中客户端400、已登记上游400、结构化错误码严格等于input_too_small时生效。客户端响应正文、HTTP状态、原始上游消息/详情、计费、缓存和协议转换不变。
- 管理员渠道分类详情优先使用该规范化摘要，使明细与分钟统计一致；其他详情保留原来的上游消息优先级。
- 没有修改统计taxonomy版本、数据库结构或服务器容量配置，也没有通过改长提示词绕过上游规则。
