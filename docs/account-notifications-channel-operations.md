# 账号通知与渠道运维

本模块复用 ranxi2001/sub2api 的账号通知和渠道运维实现，保留 LGPL-3.0 归属；参考提交为 `9620d315f72a7dbf04fa10fca02970e1e410805e`。

账号通知默认关闭且没有预设目的地，不修改原有 Bark、余额邮件或网关错误规则。管理员可分别设置余额/额度阈值的预警、恢复通知和邮件、企微、钉钉、飞书、通用 HTTPS Webhook。通知事件按状态转换持久化；多实例领取使用数据库租约；已成功的通道在重试时不重复发送。缺失、失败或过期样本不会被当作恢复。

Webhook URL 与签名密钥使用现有固定安装密钥加密，读取只返回已配置标记。通用 Webhook 使用现有 SSRF 安全连接器，保存时静态校验、连接时校验实际 IP，并禁止跳转。请求失败只返回固定错误，不泄漏目的地和上游响应。

余额读取复用现有账号计费探测。需同时打开探测总开关、账号探测和对应余额阈值规则；其他账号不会因为新增通知模块而增加 `/v1/usage` 请求。读取失败不改账号倍率、调度或余额账本。

渠道运维增加人工的“渠道 → 上游标签 → 账号”归属。账号仍使用原渠道分组选号，运维标签不参与实际路由或价格。修改需要 revision；改派、解除和删除需确认。历史用量按其已保存的 channel_id 加当前标签分析，不伪称历史上游归属。TTFT 只统计实际保存且有用量证据的流式样本，未知值不计为零。时间窗口最长 31 天，查询限时，失败明确显示而非返回成功的零数据。

质量下钻使用本站现有掺水检测结果：一次保存的 audit 为一次样本。仅当保存的终态与检测结论一致时显示通过或降级，其他情况为不确定；模型只取结果内保存的名称，不用当前计划推断历史模型。数据库安全摘要函数只返回白名单字段；探测正文、凭据、审计 URL 和远端检测编号均不返回。

所有新增管理接口在 handler 内硬限制 ID1，观察者管理员不能读取上游账号详情或修改规则。通知目的地的修改、删除与测试须接现有新鲜 2FA/step-up；普通阈值和冷却参数不需要额外验证。

迁移 280～282 为通知表；283 为独立运维分类；284 为安全质量摘要函数。回退旧二进制前关闭新通知总开关；这些附加表和函数可保留，不影响旧版网关。代码和测试完成不等于生产已启用，发布须以 GitHub CI 结果为准。
