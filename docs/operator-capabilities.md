# 诊断、运维与专项通道

本分支定向适配 `ranxi2001/sub2api` 的运维能力，参考提交为
`9620d315f72a7dbf04fa10fca02970e1e410805e`。保留 LGPL-3.0 来源说明与
各协议目录的 NOTICE；不导入对方的业务配置、模型别名、成本倍率或默认账号。

## 从哪里开始

| 需要解决的问题 | 后台入口 | 默认行为 |
| --- | --- | --- |
| HTTP 成功但流式中断、客户端取消、出站连接失败 | 诊断与运维 → 连接诊断 | 区分应用与入口代理的观察，不把两者当作同一连接证据 |
| 对照入口、出站、上游及下游报文 | 诊断与运维 → 请求采集 | 普通定向采集与 ID1 八小时持续诊断分别默认关闭；先配置稳定实例标识 |
| 比较重复长前缀的缓存用量、延迟和费用 | 诊断与运维 → 分组缓存测试 | 手动执行；复用当前用户有权使用的单组 Key，走真实计费路径 |
| 查看请求及响应的传输量 | 诊断与运维 → 用户流量；用户流量页 | 统计流量字节，不将字节冒充 Token；用户仅看自身记录 |
| 某时刻开启或关闭账号调度 | 账号列表 → 定时调度 | 没有计划时不执行；可编辑、取消，按明确时区显示 |
| 额度、错误及恢复通知 | 诊断与运维 → 账号通知 | 显式配置接收方和规则，独立记录各通道的送达情况 |
| 从渠道下钻到人工供应商和账号 | 诊断与运维 → 渠道运维 | 复用既有用量和质量证据，不启动额外视觉评审 |
| 托管订阅和代理内核 | 诊断与运维 → 代理出口 | 不安装、不启动内核；需要站长自行配置 |
| 巡检凭据、受控重新授权 | 诊断与运维 → 凭证巡检 | 自动重登关闭；只使用显式批准的服务，403 转人工处理 |
| 新 OAuth 模板、成功升并发、质量和额度排序 | 诊断与运维 → 账号自动化 | 各项分别关闭；不更改倍率、模型映射、分组遍历顺序或已有会话 |
| 按国家地区分配已有在线网关 | 诊断与运维 → 地区路由 | 关闭；所有网关仍共享在线数据库和 Redis |
| 邮箱别名格式和 API 安全限制 | 系统设置 → 注册；安全审计 → 分层安全限制 | 别名拒绝关闭；分层限制关闭且默认为观察 |

完整管理员操作限制为主管理员。观察者管理员继续使用既有的脱敏使用记录，
不能读取采集正文、代理凭据、上游授权或其他用户资料。用户安全记录页只显示
当前登录用户的原因、范围与期限，不返回审核原文或其他用户的数据。

## 必要的配置与权限

Key 页可单独设置并发上限。`0` 表示不增加 Key 级限制；用户自己的并发
`0` 仍表示不限。Key 等待队列复用 Redis 租约，等待超时、取消和重新授权
均有明确处理；不会在等待期间持有上游账号槽位。

请求采集按稳定部署槽位管理。各蓝绿槽位必须使用不同的
`SUB2API_CAPTURE_INSTANCE`，并通过定向入口管理同一实例。正文查看和导出
使用现有主管理员 2FA 验证。结构化凭据会脱敏，但自由文本可能包含秘密，
不能将采集内容直接公开。见 [采集部署说明](../deploy/request-capture.md)。

通知接收方、Webhook、重新登录凭据、Excel 授权等敏感变更复用现有 2FA；
普通阈值、冷却时间和展示设置不额外增加验证步骤。敏感字段不进入普通审计正文。

Mihomo 本机管理入口和共享数据面分开配置；共享代理必须显式启用私网、
认证及允许名单。删除受管代理应从节点页释放，仍有账号引用时拒绝移除。

## 专项协议

| 能力 | 使用条件与边界 |
| --- | --- |
| Gemini `cachedContents` | 原生 Gemini API Key 与上游明确支持；资源绑定原用户、Key、组和账号；创建及续期使用持久幂等账单，结算完成前不可引用 |
| Copilot SDK | 单独部署授权后的 SDK 适配服务，并在账号上开启；保留原生 Responses 工具及历史，客户端身份绑定真实站内 Key |
| Excel/BPS | 需要独立完成 Excel OAuth 授权；凭据与普通 Codex 授权分开加密，不能将普通 OpenAI OAuth 当作 Excel 授权 |
| Seedance Ark | 上游明确支持原生异步任务，账号能力需主动开启；任务绑定创建账号，由后台轮询及幂等结算 |
| MiniMax-H3 | 第三方 JSON Videos 兼容接口，需要非 Coding 账号及明确单价；可按生成秒数或指定固定时长按次收费 |

专项通道不提供公共凭据，也不保证任意上游支持相同协议。CI 的合成协议测试
与页面预览用于验证本站集成；真实提供商授权、额度、网络及价格需由站长核对。

## 自动化和升级

质量检测需要完整成功终态。取消、断流、空答案或判题不确定不会被解释为
质量失败；模型和分组隔离保留独立归属，恢复时不会覆盖人工修改。
先测后放行及 OAuth/API 后备只在有相应完整终态、额度和容量证据的平台启用，
未满足条件时不猜测放行。详见 [账号自动化](account-automation.md)。

地区路由仅管理已有在线网关，不创建 Pod，不提供离线鉴权或离线账本。
已有会话继续绑定原网关，不在部分响应后跨节点重放。
配置与信任边界见 [地区网关路由](regional-gateway-routing.md)。

迁移通过现有迁移工具执行，业务进程继续使用 `DATABASE_MIGRATION_MODE=validate`。
上线前先关闭尚未准备使用的新自动策略，保留原实例处理中的长连接。
回退前应关闭新策略并核对其持有的隔离标记、待结算缓存和异步视频任务，
不要直接删除附加表、后台账单或仍在使用的代理监听。
