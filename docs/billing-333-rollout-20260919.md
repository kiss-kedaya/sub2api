## 修复范围

- Responses WebSocket 每轮结算完成后重新检查余额、订阅；结算失败或超时不继续下一轮。
- Grok 视频创建时冻结实际路由组、价格、倍率和订阅身份，并持久化资金预留；后台独立查询终态，用户不轮询也不会漏扣。
- 视频状态与下载先完成持久化结算；同一任务跨实例只扣一次。已有预留的任务不会因为可用余额归零、Key 改组而无法下载。
- 明确拒绝/失败的视频释放预留；无法确认上游是否接单的传输错误保留记录等待对账，不重发、不猜测退款。
- 异步图片结算意图先落库；未结算结果使用私有 `pending_result`，331 读取时也不会公开。缓存短暂失败有界重试，结算恢复后再公开。
- 批量图片上游已接单但首次入队失败，后台自动补队，不重复提交上游。
- 退款 pending 保留原扣减，明确失败才释放；成功不会二次扣减。
- 流式追加预扣持久化累计金额；Redis 成功、PG 失败时停流并保留恢复依据。
- 上游拒绝免扣优先于免费 Fast 重算；已知模型变体继承分组价，精确/通配价格仍优先。
- 已生成图片不重复做订阅准入；实际费用仍可落账。订阅零限额沿用无限语义。
- 未定价的标准模式 Live 明确拒绝，不开放免费消费入口。
- 媒体结算读取用户和账号当前提醒设置，保留已冻结的账号成本倍率；提醒信息读取失败不改变费用，联系方式和凭据不进入结算快照。

## 经验与边界

- Redis claim 不能代表已扣费；数据库结算记录才是资金幂等依据。
- 预留、实际组身份、单价必须在创建时冻结；查结果不能重新选路或按入口首组重算。
- 旧版本会忽略新增字段；滚动升级必须检查旧读取器是否泄露未结算结果。
- 后台每次处理前单独领取任务租约，避免慢请求耗尽队列中其他任务的租约。
- 资金变更已有数据库 outbox 时，不再重复发送 Redis 余额调整。
- 只持久化 ID 的后台任务仍需恢复非财务副作用所需的设置；金额正确不代表余额和渠道额度提醒仍然正常。
- 本机出口在候选尚未启动前被 Cloudflare 返回 403；两台服务器通过公网访问健康接口正常。未修改 WAF 或将该既有出口限制归因于新版。
- 上游接单结果未知的任务仍需要对账；对象存储持续故障或进程恰在结果保存前退出仍可能导致结果待人工恢复，不能把有界重试称为绝对不丢单。
- 未自动追扣历史账单，未修改真实用户余额、分组定价或暂停的视频账号。
- 生产视频账号若仍不可调度，必须明确记录真实视频验账未完成，不能用模拟账本数字冒充实单。
