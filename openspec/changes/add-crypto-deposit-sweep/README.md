# 内置链上充值与归集：当前实现

本目录保留早期提案和设计草案。除本文件外，带有“历史设计说明”的文件用于追溯需求，不作为当前运行契约。部署及恢复操作以 [支付配置指南](../../../docs/PAYMENT_CN.md) 和 [Docker 文档](../../../deploy/DOCKER.md) 为准。

## 功能与入口

- 用户从 `/deposit` 获取独占充值地址、二维码和充值流水。EVM 地址由充值种子和稳定索引派生，支持配置中的 BSC、Polygon、Plasma、Arbitrum、Base、X Layer；代币合约与 decimals 按链校验。
- 扫描器确认链 ID、规范区块与真实 Transfer，再通过已有余额订单履约服务入账。交易身份包含链、交易哈希和日志索引，重复扫描复用原订单；已入账金额以持久订单为准。
- 归集只处理已入账且未归集的台账金额，先 dry-run 核对目的地和额度。Gas 补款与代币转账的签名原文先持久化再广播，未知结果复用同一交易继续确认。
- 扫描与归集使用数据库会话锁协调实例，配置更新与手动操作在进程内串行，失败不会伪报为完成。

## 钱包和权限

钱包在主 `sub2api` 进程内派生和签名；不提供独立 signer 容器、socket、policy、签名文件、额外钱包密码或手动解锁。旧 `crypto.signer.vault` 设置键和 `crypto_signer_audit` 表名保留用于数据与迁移兼容。

充值和 Gas 使用两份独立助记词。种子以 AES-256-GCM v2 密文保存，钱包子密钥由固定 `TOTP_ENCRYPTION_KEY` 独立派生。重建实例必须保留安装密钥；安装密钥及助记词的恢复能力见支付配置指南。

支付后台需要登录、现有管理员身份、启动时固定的 `CRYPTO_ADMIN_USER_IDS` 和安全传输。种子导入/导出、Gas 种子更换、归集地址和配置修改、扫描与归集等危险操作必须逐次通过后端 2FA；验证码不能重放。未绑定时引导生成密钥及二维码，完成后端验证后绑定。

首次初始化需要两份助记词，不能覆盖已有充值钱包。导出默认遮罩，两份助记词分别拆成两段复制，关闭或超时清理。更换 Gas 种子不改变充值种子，存在未完成归集时拒绝更换。

## 独立测试实例

`CRYPTO_ADMIN_TEST_MODE=true` 保持启动隔离、迁移只校验、独立 JWT 及后台任务抑制。默认业务只读；只有显式 `CRYPTO_ADMIN_TEST_WRITE_ENABLED=true` 才放开受保护的支付写操作。网页和请求头不能改变这些进程级开关。

后台关闭时可调用逐次 2FA 保护的 `POST /api/v1/admin/crypto/scan/run`，请求 `{}` 续扫，单链配置下可用 `from_block` 回看最近 100000 块内已确认区间。单次超时后先检查充值记录，再从已保存进度继续。

## 验收边界

- BSC 主网 USDT 的两笔小额充值、正式余额入账、原区间重扫防重复、单次 Gas 补款及归集已完成真实验证。
- 多链、金额精度、确认/重组、持久化失败、签名约束、归集恢复、2FA、权限及前端交互另有自动化测试；自动化覆盖不等同于每条链均完成主网资金验收。
- Solana 派生工具不代表已实现 Solana 收款、扫描或归集；不列为当前交付能力。
- 默认总开关关闭，自动归集需明确配置。独立测试模式不会自动启动共享生产后台任务。
- 迁移以完整文件名及 checksum 标识；保留已发布迁移内容，不能因为数字前缀相同而改名重跑历史迁移。
